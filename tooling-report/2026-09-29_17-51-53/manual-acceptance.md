# 人工复查与尚未执行的平台验收

依据 requirement/v0.1.0。请使用独立测试 Profile 与虚构数据；本文件是复查步骤，不是通过证据。

## 基础体验与 UI

1. 安装本轮 team-lab.amble-extension（example.team-lab，Demo 0.2.0），确认代码信任。未授权时只见空状态，不应出现未授权项目内容。
2. 新建两个业务任务；第一项创建聊天 A/B，下拉框分别打开。创建只保存草稿；发送须在宿主完成。
3. 在另一窗口修改/归档/删除已打开的草稿，再尝试发送。原输入须保留，旧内容不得执行。仅版本变化且内容未变可发送。
4. 宿主设置中编辑 Demo 的 serviceUrl、connected、density、limit；limit 必填，错误类型/越界应拒绝。双窗口同时编辑，后保存旧版本应冲突且保留输入。
5. 切换中英文与亮暗主题，检查入口/命令/配置说明/页面/通知来源。用户输入名称不翻译；后台 l10n 动态更新属于已记录的宿主缺口。
6. 使用键盘 Tab/Shift+Tab/Enter 操作按钮及下拉框，调整为窄窗口；默认技术回执应折叠，内容不横向溢出。
7. 发布稳定 eventKey，重复发布；阅读后更新，检查不新增未读；拒收后同 key 不复活，已清除后仍 dismissed。动作按钮不属于已实现能力。
8. `npm run service` 启动本地服务，配置回环 /events。按 Demo README 的 curl 发送新/重复/乱序/撤回事件；两窗口时 /stats 只有一个有效连接。改地址、关闭连接、停用/卸载应释放旧连接。

## MSG-14：系统横幅与点击（本轮 NOT-RUN）

1. 在测试系统确认当前 Electron/发行应用的通知权限及系统专注模式；不要将 Notification.isSupported 或 remind=true 当作实际横幅。
2. 开启来源接收、关闭静音，用新 eventKey 发布。实际观察系统横幅并保存去敏截图、时间、eventKey 和平台版本。
3. 点击横幅，应打开/聚焦宿主消息中心；截图记录实际导航，不能直接调用私有导航 IPC 充当点击证据。
4. 来源静音后以另一个新 eventKey 发布：消息中心有记录和未读，不应主动横幅。拒收后新事件不应产生可见记录或横幅。
5. 系统权限或平台限制阻止观察时，记录 NOT-RUN/平台条件，不修改为 PASS。Windows/Linux 和签名发行包需各自独立运行并保存证据。
