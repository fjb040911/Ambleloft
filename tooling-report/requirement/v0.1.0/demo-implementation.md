# 全场景扩展 Demo 施工与验收

需求版本：v0.1.0。目标：把“团队任务演示”升级为可供开发者学习、用户试用和自动验收的扩展，覆盖当前宿主能力的正常、异常、跨窗口及重启流程。不是只跑一次成功路径的展示页。

## 1. 产品结构与使用流程

Demo 名称保持团队任务演示，可增加“功能验收”子页面。业务区使用普通用户理解的语言，技术回执独立折叠，禁止以 JSON 作为默认操作界面。

首页提供四个区域：

1. **项目与聊天**：当前关联项目、任务列表、聊天关联，分别提供“新建聊天”和“打开已有聊天”。不得把打开按钮暗中变成创建操作。
2. **通知**：发布进展、更新内容、撤回；独立展示发送结果。提供前往宿主消息中心的文字指引；没有公开导航 API 时不能伪造链接。
3. **服务连接**：可选本地演示服务的连接状态、连接/断开、最近收到的业务事件、重连状态。默认无需服务器也能使用本地功能。
4. **运行信息**：包版本、后台实例标识、可用预览能力和最近操作结果；详细错误、revision 等仅在开发者区展示，不显示密钥。

配置入口使用设置 → 扩展 → Demo → 扩展设置。Demo 页面展示生效配置与设置位置指引，不私自写 configuration。账号相关页面明确“待宿主支持”，不冒充可登录。

## 2. 页面与 UI 定义

DEMO-UI-01：用 extension.json 声明包内首页、入口命令、Operation、权限、激活事件、contextKeys 和中英文词典。每项写明目的、调用方、读写效果及请求权限。

DEMO-UI-02：提供至少一个始终显示的命令、一个受 when 控制的命令、一个受 enablement 控制的 Operation；显示条件和执行权限分别验证。未关联项目时显示可理解的空状态，引导用户选择并授权项目。

DEMO-UI-03：遵循宿主现有 Apple 风格，统一图标线条、色彩、按钮层级；覆盖亮暗主题、中文/英文、长名称、窄窗口、键盘焦点、错误恢复、加载和禁用状态。不自行模拟宿主确认弹窗。

DEMO-UI-04：需要修改内容时仍经过宿主确认。扩展按钮文字不能代替确认。验证取消后不派发；已获项目授权也不自动免确认。若用户在宿主明确选择符合规则的记住授权，按当前宿主策略验证，并测试撤销后再次询问。不得把开发者声明的描述冒充宿主核实的事实。

## 3. 项目与聊天：核心业务闭环

Demo 维护自己的 taskId → projectId → conversationId 关联，不把工作目录当作项目身份。一项任务可拥有多个聊天，必须能选择打开哪一个，不能全局只保存一个 conversationId。

- “新建聊天”：用户选择任务、填写标题/初始内容，显式调用 createConversation，保存返回 ID，再打开。创建不调用模型。
- “打开已有聊天”：明确指定所选 conversationId，不新建、不自动重发内容、不自动还原归档。
- “再建一个聊天”：独立按钮，生成新 ID，不覆盖旧关联。
- 当宿主未提供归档状态查询时，列表显示“已关联聊天”，不假装知道它未归档。打开后的归档交互由宿主处理。
- 聊天永久删除后，不自动创建替代聊天。显示原关联无法打开，由用户选择解除关联或新建。
- 创建请求结果未知时不自动重试；避免创建重复聊天。缺乏查询能力时明确保留待核对状态。

## 4. 通知与三种订阅

### 4.1 扩展发布到 AmbleLoft 消息中心

使用真实 context.messages 五方法。提供稳定业务 eventKey，显示“已发送／已存在／用户已关闭接收／已清除”，不将所有返回都显示成功。

用户可以在宿主读取、清除和设置接收偏好；Demo 不读取内部 readAt/dismissedAt，不通过私有 API修改偏好。宿主内置 AmbleLoft 来源与扩展来源并列，消息中心不依赖 Demo 存在。

### 4.2 扩展订阅自己的服务推送——本版必须演示

新增可单独启动的本地测试服务，协议固定一种即可（推荐 WebSocket），无需企业账号或外网。明确它是 Demo 自己的业务服务，不是宿主消息订阅 API。

服务事件至少包含 eventId、taskId、kind、内容版本和消息内容，支持产生、重复、乱序、断线、撤回测试。Node 后台连接服务，将适合用户查看的业务事件转换为通知；扩展页面只展示状态，不另开同一订阅连接。

- 未配置地址时不连接，页面给出启动说明；本地功能仍可用。
- 连接由一个后台实例持有，同一 Profile 两窗口不应产生两份订阅或重复通知。
- 使用有上限的退避重连；超时/错误处理、关闭清理、手动断开、配置变更重连必须实现。
- 稳定 eventKey 抵御重复事件；旧业务版本不能覆盖新内容。不能把迟到事件当成新事件不断增加未读。
- 若宿主当前不能保证多窗口单后台、隔离 Profile 或停止旧 generation 写入，记录 BLOCKED-HOST，不靠禁用第二窗口规避。
- 服务监听回环地址，进程退出释放端口。测试控制接口只供测试使用，不访问真实企业服务。

### 4.3 宿主事件订阅——准确标识边界

已实现：configuration.onDidChange、页面 onHostContextChanged；均须实测注册、更新、dispose。

内部 UI：消息中心通过宿主事件刷新，测试跨窗口通知即可，不向 SDK 暴露 window.desktop.messages.onChanged。

待支持：扩展订阅 Agent 完整回合、通用消息到达、其他扩展消息、通知偏好变化推送。列出需求与预期，不声明为通过。没有偏好变更订阅时，可在业务事件到来后调用 getPreferences，或直接 publish 并处理 rejected；不要构造假的事件 API。

## 5. 设置、存储与本地化

声明 configuration/self 权限，包含：演示服务地址（string）、是否连接（boolean）、展示密度或通知级别（enum）、数量限制（integer）、至少一个可选字段。复杂 array/object 可加入开发者页验收，按现有宿主 JSON 编辑方式呈现，不宣称已有嵌套可视化表单。

不能使用 schema 尚不支持的 title/default/字段 when。字段说明使用 nls。应用侧默认值集中定义，README 明确恢复默认值意味着宿主清除配置、扩展回到自身默认行为。

设置变更必须立即影响后台连接或显示行为；同一对象反复更新不能堆积监听器。active 后台收到变化，未激活后台下次启动读取最新值。重启保留配置。授权不足要说明并引导授权，不绕过授权。

普通 KV 存业务关联；secrets 只用虚构测试密钥演示宿主安全输入、后台读取及删除。没有安全加密后端时明确失败，不落明文。中英文切换覆盖入口、贡献标签、配置描述和页面；Node 后台动态 l10n 当前不足须单列，不通过悄悄重启整个应用掩盖。

## 6. 必须执行的验收矩阵

每行记录前置条件、操作、断言、实际结果与证据。自动化优先，手工项也要保存可复查步骤；不能仅检查按钮存在。

| ID | 场景与操作 | 必须断言 |
| --- | --- | --- |
| UI-01 | 安装并首次打开，无项目授权 | 正确空状态；不枚举未授权项目内容；无假成功 |
| UI-02 | when 从 false 切 true 再切 false | 管理命令隐藏/出现正确，后台执行仍校验 |
| UI-03 | enablement=false 直接 invoke | 明确拒绝，不派发；与 when 区分 |
| UI-04 | 中文→英文、亮→暗，第二窗口同时打开 | 入口、命令、通知来源、配置描述、页面随当前语言更新，合理回退 |
| UI-05 | 长名称、窄窗口、键盘操作、打开关闭页面 | 无遮挡/焦点丢失，监听释放，不额外生成业务记录 |
| UI-06 | 取消宿主确认；记住后撤销 | 取消零副作用；撤销后恢复确认；页面不能自报批准 |
| CHAT-01 | 新建 A 并打开，不发送 | 只有一个草稿，无 run/模型调用；回执 ID 与宿主一致 |
| CHAT-02 | A 首次发送及后续继续 | 同一 conversationId，业务关联仍指向 A |
| CHAT-03 | 打开 A 多次 | 不重复创建，不重复注入或发送用户消息 |
| CHAT-04 | 同一业务任务新建 B | A/B ID 不同，列表可分别打开，A 关联保留 |
| CHAT-05 | 归档草稿 A，再从扩展打开 | 展示归档交互，不进入可误发送状态，不自动还原或创建 |
| CHAT-06 | 明确选择还原并继续 | 原 ID 保持，归档解除，发送成功 |
| CHAT-07 | 归档草稿选择复制/当前内容新建 | 新 ID，与旧 ID 分离，旧草稿仍归档 |
| CHAT-08 | 打开草稿后在另一窗口修改/归档/删除 | 发送前核对，不执行旧内容；用户输入保留，恢复路径可用 |
| CHAT-09 | 仅版本变化、内容未变 | 采用最新版本，发送成功；提交时仍有事务校验 |
| CHAT-10 | 已执行聊天归档/删除后扩展再次打开 | 不自动执行/复活；归档可查看或提示还原，删除明确失败 |
| CHAT-11 | 不传/空 ID、未知 ID、跨项目 ID | 不隐式创建，返回真实错误，不泄漏未授权内容 |
| CHAT-12 | 项目重命名、删除或授权撤销后调用 | 不使用失效范围；可理解错误；不改变旧聊天 ID |
| MSG-01 | 新事件、同 key 重复发布 | published→duplicate，只有一条消息、一次首次提醒意图 |
| MSG-02 | 更新正文后查回 | revision 递增，另一窗口刷新，eventKey/来源不变 |
| MSG-03 | 标记已读后更新 | 保留已读，不新增未读或主动提醒 |
| MSG-04 | 旧 revision 更新/撤回 | CONFLICT 原样可判别，原内容不被覆盖，不自动重试 |
| MSG-05 | 撤回、过期、已完成后更新 | 不恢复有效待办；记录保留，终态约束有效 |
| MSG-06 | 拒收新事件、再打开接收并重发同 key | rejected 保持，不复活；查询无可见结果 |
| MSG-07 | 拒收期间更新/撤回已有消息 | 允许状态更新，不增加未读/提醒 |
| MSG-08 | 静音后发布 | 仍有消息与未读，无主动提醒意图；解除后只影响后续事件 |
| MSG-09 | 用户清除再查/重发 | 查询 null，同 key dismissed，不重新出现 |
| MSG-10 | 全部已读/按来源筛选/清除已读 | 范围正确；待办保护符合现行规则，不误清其他来源 |
| MSG-11 | 重启后重复发布、恢复列表 | 记录、版本、已读、拒收标记和偏好保留 |
| MSG-12 | 双窗口读消息/改接收设置 | 同步更新；扩展不获得 readAt/dismissedAt |
| MSG-13 | 非空 actions、伪造来源/账号、非法超大输入 | 真实拒绝，无假消息按钮或跨来源写入 |
| MSG-14 | 系统通知允许/静音/拒收/点击 | 支持平台观察横幅与打开消息中心；权限受系统阻止时记 NOT-RUN，不用 remind 代替系统实测 |
| SUB-01 | 本地服务推送新事件 | 真实后台收到并发布通知，页面不直接写宿主消息 |
| SUB-02 | 两窗口打开 Demo | 服务端观测一个有效订阅连接；同事件一条通知 |
| SUB-03 | 服务断线、重启、重复与乱序事件 | 有界重连、去重、旧版本不覆盖；无无穷重复提醒 |
| SUB-04 | 改地址/关连接、停用/卸载 | 旧连接释放，旧 generation 的在途回调不能写入 |
| SUB-05 | 配置/context listener dispose | 释放后不再回调，重复开关页面不堆积 |
| CFG-01 | 未授权访问配置，后通过宿主授权 | 前者拒绝，后者读取成功；信任安装不自动授权 |
| CFG-02 | 设置页编辑 string/enum/boolean/integer | 保存后后台 get 与 change 事件一致，刷新/重启保持 |
| CFG-03 | 不合法类型、必填缺失、越界、复杂 JSON 错误 | 保存被拒绝，旧有效配置未覆盖 |
| CFG-04 | 两窗口打开配置，先后保存 | 旧 revision 冲突，输入保留，不静默覆盖 |
| CFG-05 | 恢复默认值 | 宿主清除配置、后台收到空对象、应用默认行为恢复；重启一致 |
| CFG-06 | 未保存退出、扩展升级/停用时保存 | 有退出保护；generation 变化拒绝旧表单写入 |
| DATA-01 | KV null、缺失、CAS、删除再创建 | 返回语义正确；revision 单调，旧写入不能穿透 |
| DATA-02 | 测试 secret 输入/后台读取/删除 | 页面和日志无秘密；跨扩展读取拒绝；加密不可用不降级 |
| LIFE-01 | 安装、激活、关闭页面重开、重载开发包 | 状态和实例变化符合设计，业务数据保持，无额外后台 |
| LIFE-02 | 在途写操作时停用/卸载 | 后续调用拒绝，过期实例不能写；历史通知按设计保留 |
| LIFE-03 | 后台崩溃、超时、取消 | 用户可恢复；不自动重放未知结果的写操作 |
| LIFE-04 | 应用重启、安装版本更新/回退 | 数据和身份保持，旧确认/权限版本不能误用于新实例 |
| AGENT-01 | Agent 发现并调用声明 Operation | 项目范围、输入、确认、错误和返回正确；不借页面桥绕过 |
| AGENT-02 | Agent 尝试页面交互能力或无权限操作 | 拒绝或要求用户交互，不伪造用户点击 |

消息中心状态矩阵需引用 specs/extensions/message-center-design.md。无法用当前 actions=[] 覆盖的“业务完成、按钮及恢复”标准必须列 BLOCKED-HOST，不为填表伪造内部写入接口。

## 7. 施工顺序

1. **D0 能力审计**：落实 SDK-01，对本表逐行映射，先识别阻塞项和精确调用入口。
2. **D1 SDK/CLI 对齐**：完成 sdk-requirements.md，隔离安装包及模板验证。
3. **D2 本地 Demo**：先完成 UI、配置、项目、多聊天、归档恢复及通知五方法，无服务也可体验。
4. **D3 业务推送**：增加本地服务、后台连接与订阅状态机；不引入企业认证依赖。
5. **D4 联调**：真实宿主执行矩阵，修复缺口后逐项重跑；宿主问题单独反馈宿主 Agent。
6. **D5 交付**：README、开发教程、可安装包、模板、完整测试与结果；明确 PASS 和 BLOCKED 范围。

## 8. 环境与证据

- 使用独立临时 Profile、本地项目与虚构数据；不改变用户日常配置，不依赖真实企业账号。
- 验收必须运行真实 Electron、扩展进程、页面桥、RPC、数据库和窗口。禁止用 stub 替代待验证宿主能力。
- 模型固定响应服务仅用于执行链路；本地推送服务是业务输入夹具。报告明确二者不能代表真实模型质量、互联网服务或企业 IdP 兼容性。
- 页面测试可 mock 便于定位，但不替代真实桌面验证。至少 macOS 双窗口；未执行 Windows/Linux、签名安装包或系统横幅检查必须显式写明。
- 每次运行保存用例 ID、参数摘要（去敏）、时间、结果、关联 ID、版本、错误码、包/源码 hash、日志和关键截图。失败也输出报告并清理进程/临时资源。
- 不截图或记录用户 Token、密码、真实企业数据。不要只以“测试数通过”宣称所有能力完成；给出矩阵的通过、失败、阻塞和未运行数量。

## 9. 完成标准与交付清单

可交付的实现必须满足所有当前宿主可用项；阻塞项保留独立清单，附最小复现和后续验收步骤。带阻塞可交付阶段成果，但不能称“全部宿主能力验收完成”。

交付至少包含：SDK/CLI 包及 changelog、Demo 源码与安装包、本地推送服务、配置样例、模板生成说明、自动化测试、人工测试步骤、能力矩阵、测试报告、证据索引、宿主问题清单。

重点防止本轮遗漏再次发生：打开≠创建、归档≠删除、权限≠确认、发布回执≠已送达系统通知、配置声明≠默认值支持、内部模块≠公开 SDK 能力。
