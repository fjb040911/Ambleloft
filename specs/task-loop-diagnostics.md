# 任务空转保护与复现诊断

## 使用方式

更新后重启 Ambleloft（修改涉及 Electron 主进程）。无需打开调试开关，也无需让模型生成分析报告：应用自动记录每次模型请求的脱敏元数据。

1. 使用原来相同的模型、服务、权限和任务内容重新尝试。记录复现时间；不必反复要求模型“必须复现”，模型行为并不确定。
2. 出现空转时，应用会先向模型注入纠正提示；持续空转则暂停。用户也可以随时停止。
3. 在暂停/错误提示中点击 **导出诊断数据**。也可以点击回复下方的模型名称，在模型详情中导出。
4. 将导出的 JSON 和“原任务目标、期望行为、复现时间、是否手动停止”一起提供给开发者。无需发送整个用户数据目录、完整数据库或服务密钥。

一次较小的工具切换复现场景可以使用以下提示词（不保证模型再次陷入循环）：

> 请启动一个持续约 20 秒的临时终端命令，开始时输出 started，结束时输出 done，不修改项目文件。首次等待约 1 秒，如果工具返回运行中的 session_id，请用实际提供的会话轮询工具继续读取该会话，直到结束，最后报告退出码。不要重新启动同一个命令，也不要用 echo 代替轮询。

这能覆盖 `exec_command` → `write_stdin` 的交接。若要复现原任务特有的问题，应仍使用原任务；模型自述“我需要调用某工具”不能证明实际调用了该工具，以诊断数据为准。

## 当前保护规则

- 作用于本次运行中的各引擎线程，父任务与子代理分别计数。用户新一轮继续会重置检测，实时追加用户指令也会重置。
- 连续 6 次纯 `echo`/`printf`/`true` 空转，或重复的相同工具、参数、结果，先提醒模型。持续至 12 次则阻断下一次模型请求，并将任务标记为中断，显示专门的暂停原因。
- 重复检测覆盖长度 1–3 的短循环；命令输出中的耗时、块编号不视为进展。
- `write_stdin` 返回仍在运行、原生 `wait` 返回等待超时，以及命令返回后台运行中的会话，不计入空转。不存在的会话持续报同一个错误则会计数。
- 新结果/新调用打破原重复序列；包含重定向、命令替换或复合操作的 shell 命令不会仅因含有 `echo` 被当成纯空转。
- 暂停复用现有中断机制，并暂停待发送的输入。不会自动换模型、替用户批准权限或自动重试。已经产生的文件或远端副作用不回滚；继续前需要核实。
- 这是保守的启发式检测，不是任务是否完成的语义判定。不断变化的无效操作、任意长的循环或不在请求历史中的工具结果可能不会触发；合法但反复产生相同结果的调用也可能需要手动继续。正常长等待本身不设为异常。

## JSON 包含什么

导出本任务最近 **100 次** 请求。包含请求 ID、线程/轮次、时间、协议、HTTP 状态、结束原因、服务报告的 token 用量（如有）、提供的工具名称和参数类型/必填项、返回工具名称与映射名称、参数/结果的比较指纹、保护计数与动作。Chat 与流式 Responses 均记录工具身份。

不导出聊天正文、模型思考正文、命令文本、参数值、工具输出、服务地址或密钥。参数与结果使用每轮随机密钥的 HMAC 指纹，密钥不保存；指纹仅供同一轮内部比较，不能跨轮比较。工具定义不保存 description、默认值、enum 值或完整 schema。

升级前的旧请求只有原有基础诊断，无法补录未保存的工具定义或上游返回信息；应重启后重新尝试。导出是点击时的快照，不会上传到服务器。

分析时重点检查：

1. `tools` 是否提供 `write_stdin`，其 `schemaType` 是否为 `object`，`session_id` 等参数是否存在。
2. `calls.returnedName` 和 `calls.mappedName` 是否一致。若两者均为 `exec_command`，不能用模型正文中提到 `write_stdin` 作为发生映射错误的证据。
3. `observations` 中的 `noop`、`polling` 和指纹是否显示持续空转，是否有结果变化。
4. `loopGuard` 是否从 `warn` 进入 `pause`；`stage: loop_guard` 表示该次请求在到达模型服务前被拦截。
5. 对照 Request ID 查询模型网关的授权日志，进一步区分模型输出与网关行为。导出文件没有原始响应正文，不能代替服务端的完整追踪。

```sh
node --test tests/tool-loop-guard.test.cjs tests/chat-loop-protection.test.cjs tests/chat-bridge.test.cjs tests/runtime.test.cjs tests/history-pages.test.cjs
node scripts/test-chat-bridge.cjs
PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/chat.spec.ts -g 'loop pause offers' --workers=1
```

`test-chat-bridge.cjs` 使用项目固定的真实 Codex 引擎与本地模拟模型服务，故意返回空转命令，断言第 12 次后暂停、轮询工具确实提供、同一任务手动继续后可完成。它不调用外部大模型，也不在用户项目中执行任务。
