# 项目空间交互优化实现记录

日期：2026-10-26

对应 `project-space-interaction-proposal-2026-10-26.md`。用户确认的重点是“进入空间后，清楚知道进展和下一步”。本版落地概览、任务、文档、讨论和配置入口的交互改造，沿用五个页签和现有执行服务。

## 已实现

- 概览优先展示需要处理的事项，覆盖等待输入或授权、待验收、失败/中断、依据过期。每项携带对象定位信息打开任务侧栏或讨论原文；同一计划执行不会在讨论和任务中重复计数。已发起单成员后续请求的旧失败不重复占据待办。
- 当前计划展示已验收数量、运行状态、前置验收依赖；当前依据同时展示已采纳版本和未采纳版本。最近动态来源于真实讨论、文档更新及计划事件。
- 新建空空间保留简短引导，活跃空间不再重复展示流程介绍和四张统计卡。页面头部移除重复返回入口，收紧标题区域；页签在内容滚动时保持可达。
- 空间列表增加名称/目标搜索、需处理筛选和每次 12 条的渐进展示，按真实工作活动排序。读取、选择及空间配置更新时间不参与工作活动排序。
- 任务改为紧凑列表和 Sheet 详情；计划级操作靠近标题。详情先展示验收条件与执行证据，支持查看固定输入、依赖、历史执行以及验收意见，并说明下游影响。保留原有停止、重试、验收和依赖调度接口。
- 计划编辑拆为“计划信息 → 分配工作 → 检查并保存”，一次展开一个工作包；必填和项目范围检查在进入复核前提示。保存仍不自动启动。
- 文档列表区分正在使用的版本与最新未采纳版本；阅读视图可对照当前采纳版。采纳前依据快照计算直接工作引用及下游依赖影响，保留服务端版本并发校验。导出、撤回收进更多菜单，撤回保留原确认说明。
- 已采纳文档可以进入计划编辑，AI 规划来源及新增工作包携带该依据版本。版本对照为并排阅读，不宣称逐行差异算法。
- 讨论参与者、参考资料和历史范围改为渐进展开；显示提交状态及选择上限原因。继续讨论或重新请求单个失败成员时保留固定引用版本。重新请求需等待原讨论轮次结束，不重复请求其他成员。
- 每个空间的页签、任务筛选、详情对象与滚动位置得到保留；从侧栏或文档跳转原始任务时关闭隐藏工作台的浮层，返回后恢复详情、对照或验收备注。
- 成员的“与他讨论”和“查看任务”拆开；项目行补充已保存的 SSH 主机、端口、连接名称和容器信息，不读取或显示密码，也不推断在线状态。

## 验证

- TypeScript：`npx tsc --noEmit` 通过。
- 浏览器：`PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/workforce-spaces.spec.ts --workers=1`，13 项通过。
- 服务及展示逻辑：`node --test tests/workforce-space-presentation.test.cjs tests/workforce-plans.test.cjs tests/workforce-spaces.test.cjs`，17 项通过。
- `git diff --check` 通过。
- Impeccable 对修改的 5 个 UI/CSS 文件做过静态扫描；该扫描只覆盖文本规则，不等同于完整渲染检测。另人工检查了浅色、深色、390/800/1280 宽度截图、长标题和英文布局。
- 通过 4189 只读审阅入口检查了既有真实模型试跑记录在应用外壳中的显示，未出现页面错误。本轮未启动模型、SSH 或 Docker 执行。
- 回归过程中发现已有并行调度测试依赖 `runtime.runs[1]` 的顺序；并行任务先后变化会误报“当前工作包不可重试”。测试已改为通过工作包 request ID 选取对应运行，未改变执行服务。

浏览器测试使用明确隔离的测试数据和模拟 API，用于交互与请求参数校验；服务测试另外验证采纳、固定引用、依赖及验收约束，二者不能替代真实远端执行测试。

截图保存在本地 `output/workforce-space-review/`：真实记录概览、深色概览、窄窗口概览与验收侧栏。
