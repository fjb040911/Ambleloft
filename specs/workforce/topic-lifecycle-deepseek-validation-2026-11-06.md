# 话题任务生命周期：DeepSeek 真实模型验证

日期：2026-11-06（Asia/Shanghai）
结论：本次隔离用例通过。一个话题内完成了两项独立任务，共 3 次真实 Agent 执行；第一项任务的第二个节点由验收后自动调度。未发现此用例中的阻断问题，未修改生产业务逻辑。

## 验证环境与边界

- 使用应用现有配置 **DeepSeek / deepseek-flash**。初始化 pro6000 测试环境后，依照用户要求改用 DeepSeek；pro6000 未发起模型请求。
- 使用当前源码的 `SpaceService`、主持人、内置任务创建引导、`WorkforceService`、`PlanService`、LangGraph 调度及 `AgentRuntime`/Codex 引擎。没有替换模型响应、执行器或调度器。
- 独立数据库、空间及两名无附加技能的测试专家：资料整理员、验算专家。凭证通过原有加密存储读取并仅在内存使用，没有复制现有项目、任务或业务资料。
- 使用虚构网页状态数据，执行模式为 `discussion`（真实运行的文本分析任务），不访问网络、不读写项目文件、不调用 Agent 工具。此限制不影响模型服务的实际请求。
- **验证入口为生产服务 API，不是桌面逐按钮操作。** 同时将真实快照交给前端生产代码 `topicContext` / `topicTask` 检查状态和历史归属。本报告不将其表述为完整 UI 点击测试。

## 验证脚本

入口：`scripts/probes/topic-lifecycle-live.cjs`。

```sh
node_modules/.bin/electron scripts/probes/topic-lifecycle-live.cjs /tmp/topic-lifecycle-UNIQUE DeepSeek
```

脚本会启动隔离服务，等待该目录中的 `command.json`，每次处理后保存 `response-N.json`、`snapshot.json`、`runs.json` 和 `evidence.json`。`seq` 必须唯一，提交下一条前等待对应 response 文件。可用操作：

- `turn`：prompt；走真实主持人及任务引导。
- `confirm`：id、revision；确认草稿。
- `control`：id、revision、control（start/pause/resume/stop 等生产操作）。
- `review`：id（计划）、packageId、accepted、note；自动读取最新 attemptId/resultHash，经生产验收接口提交。
- `guard`：断言本话题已有未结束任务时，禁止另建独立草稿。
- `snapshot`：保存当前真实状态。
- `finish`：passed；关闭测试服务及数据库。

本次的全部操作和响应记录在隔离目录 `evidence.json`，未记录服务密钥。
