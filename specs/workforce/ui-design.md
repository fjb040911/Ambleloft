# 协作工作平台 UI 实施与验收标准

更新：2026-10-26。当前以[历史对话决策](../../../agent-flow/designs/agent-workforce/decision-log.md)、[需求 v0.4](../../../agent-flow/designs/agent-workforce/requirements.md)和已确认 v0.3 原型共同约束实现。此前本文把三步简化表单写为规范，属于实施反向修改设计，现撤销；不因此声称代码已改完。

> **后续决定覆盖（2026-10-26）**：角色技能与员工提交按[产品设计](role-skills-product-v1.md)、[技术架构](role-skills-architecture-v1.md)和[实施验收清单](role-skills-delivery-checklist.md)执行。下表已同步目标行为；现有代码和 v0.3 原型不因此被视为完成新设计。项目空间等其他流程保持原约定。

> **经典角色与双语补充**：按[十角色与 API 契约](expert-role-catalog-v1.md)展示本地化职责、交付及真实技能；中英文共用身份，UI 语言变化不改员工配置或产生草稿。

> **默认技能决定（2026-10-27）**：官方角色替用户配好专业技能组合，添加时预选，用户可直接沿用或调整。覆盖旧不预选规则；查看角色不安装，编辑/复制员工不重置个人选择。任务默认使用适用技能，具体证据按 AC-35～AC-38 验收。

## 1. 对齐原则

先核对业务对象、操作含义、状态及数据，再核对页面。角色库不是整个产品；需要支撑员工 → 空间 → 讨论 → 文档/决定 → 工作包 → 验收 → 历史复用。

原型代码位于 `../agent-flow/designs/agent-workforce/workforce-app.tsx`、`role-skills.tsx`、`model.ts`。原型的假数据、模型规则模拟和计时器不能搬入产品冒充能力；真实数据接入也不是删去原型业务流程的理由。

宿主外层按用户后续决定保留统一“项目 / 任务 / 协作工作平台 / 扩展”，两种侧栏模式一致。原型独立站的导航框架不照抄，正文内容和流程仍需逐项兑现。全局技能复用现有管理中心。

## 2. 页面与交互契约

| 页面/流程 | 必须呈现与可执行行为 |
| --- | --- |
| 顶部上下文 | 使用 shadcn Breadcrumb / List / Item / Link / Page / Separator；上级可返回，当前项正确标记；进入角色编辑、空间详情时反映实际层级，返回不丢草稿。 |
| 概念说明 | Dialog 标题“几个概念，一次分清楚”，说明“角色、员工和空间各负责一件事”。三条带图标内容分别解释角色模板、AI 员工、项目空间。底部“查看首次使用引导”，不能替换成全局技能管理。 |
| 首次使用引导 | 浅紫空间关系图、三个开始步骤，创建/稍后再说，随时可重看；已有数据决定完成状态；说明空间无需根目录。 |
| 角色库 | 奶油色引导区、两行标题、自设计主按钮、浅色图形；搜索与两列角色卡。卡片显示定位、职责、真实默认技能、来源版本、查看详情。标题和“查看详情”均打开只读详情，详情说明默认组合的用途与理由；只有明确“添加为我的员工”才创建草稿并一次带入默认技能。 |
| 选择起点 | 自设计提供引导/手动；查看模板不进入向导；明确添加后进入定义步骤，保留模板起点状态。遇未完成草稿先恢复或明确放弃，不覆盖。 |
| 定义角色 | 四步向导第 2 步；名称/可选方向两列，主要职责、交付、方法与边界；字段错误后可编辑。 |
| 配置技能 | 四步向导第 3 步；官方模板已选好默认组合，说明“已为这个角色配好推荐技能，可直接使用，也可调整”，可直接下一步，无需逐项勾选。名称、用途、角色理由与选择可见，提供调整技能/导入来源；技术来源进详情。不区分安装状态；取消后导航或刷新不得恢复。自定义空集合不能显示已配好。 |
| 技能选择与导入 | Dialog 内“角色推荐 / 全部技能”与搜索列表，保留独立“导入来源”入口；GitHub/本地先解析预览再勾选；取消不应用；无“已安装”页签。 |
| 确认提交 | 四步向导第 4 步；展示完整档案与所选技能。新建“添加员工”、编辑“保存更改”；提交后统一检查和补齐技能，包括导入来源，全部准备好后应用配置。不再提供“仅保存 / 保存并激活”两条用户路径。 |
| 草稿管理 | 浏览、进入编辑、切步骤不产生修改草稿；真实内容变更才暂存；恢复原值清除无效修改草稿；未修改提交不增版本、不重新安装。已有真实草稿可恢复，错误保留填写。 |
| 提交准备进度 | 检查→下载/安装→应用配置，真实逐项状态；阶段、已完成项数与可得的真实字节进度。离开后后台继续，可回看、重试失败项和恢复中断；失败时原有效员工配置继续可用。 |
| 我的员工 | 沿用员工卡片与已保存档案详情，区分有效配置与待提交配置；卡片提供真实准备状态和进度入口。添加员工进入角色库；不以进入编辑自动生成草稿。 |
| 空间列表/概览 | 清晰目标、关联项目和员工；缺项引导；不要求磁盘目录，不以成员忙碌代替目标进度。 |
| 团队与项目 | 项目环境和目录可辨；关联项目与添加员工分开管理；空间责任不覆盖员工通用档案。 |
| 讨论 | 定向选择/@、成员上下文、观点/分歧/来源与整理出口；没有采纳的内容明确为建议。 |
| 文档与产物 | 草稿、当前采纳版本、历史、来源和任务可查；新草稿不使旧决定失效；导出和权威来源清晰。 |
| 任务 | 计划、负责人、依赖、真实运行、阻塞、attempt、局部重试、验收证据与版本变更影响；无服务时不显示模拟成功。 |
| 只读编排图 | 每个协作计划提供“列表 / 编排图”切换；概览可定位进入，制定/修订计划可预览；节点展示任务、负责人、项目、真实状态与原因，点击复用任务详情。支持缩放、平移和依赖突出；状态刷新不重排或抢视角。本版不拖线编辑、不改负责人或任务，按[只读编排图设计](plan-graph-view-v1.md)实施与验收。 |
| 知识与决策 | 指向原文/来源/有效版本的查询与管理；长期记忆未接入必须明确，不能拿普通文档列表替代全部能力。 |

“选择起点 / 定义角色 / 声明技能 / 保存与激活”是历史原型四步；当前目标改为“选择起点 / 定义角色 / 配置技能 / 确认配置”，起点、草稿和确认能力保留。业务可概括成三个阶段，不允许以概括删除界面中的草稿、起点和确认内容。

## 3. 组件与视觉

使用现有 shadcn/Base UI 的 Breadcrumb、Dialog、Tabs、Field、Button、Card、Alert、Empty 等组件，遵守焦点、键盘、错误和 aria 语义。组件的正确组合比加上组件名称更重要。

保留原型 Figma 风格：系统字体、黑白工作框架、奶油角色引导、浅紫流程提示、薄荷色辅助卡；局部语义 token，深色适配。主区域一个主要动作，信息状态使用文字和图标，不只颜色。

角色卡片两列，窄容器单列；列表/弹层正文不横向溢出，长内容内部滚动，底部操作可达。宿主侧栏继续共用原有两种布局规则。动态数据、空态、断网、失败和长文案都要验收。

## 4. 验收方法

每条需求记录：来源决定 → 需求 ID → 原型页面/步骤 → 实际入口与服务 → 状态与数据变化 → 截图/行为证据 → 剩余差异。不能单凭构建、静态扫描或首页截图判完成。

至少覆盖模板到员工、自设计草稿恢复、三种技能来源、激活部分失败、员工再编辑、空空间到组队、讨论到草稿/采纳、固定版本交接、失败恢复和两种宿主导航。中英文、深浅色、窄窗口、键盘及对话框焦点随修正后的流程重新检查。

本轮检查结论与缺陷：[业务、原型与实现核对](business-audit-2026-10-25.md)。旧 [界面对齐复验](prototype-alignment-2026-10-25.md) 仅保留为历史局部证据，不能作为本规范已满足的结论。

## 5. 2026-10-26 角色详情与退出回归

角色库是模板浏览，员工列表是用户配置管理。详情提供职责、交付、方法、专业方向、技能用途与具体来源/版本；关闭不创建草稿、不安装技能，恢复原搜索和触发按钮焦点。员工档案展示实际配置版本与状态，编辑是独立动作，技能准备中不可编辑。

编辑器退出或保存后必须清除其忙碌状态；侧栏仅在提交请求尚未被持久受理的短暂阶段防重复操作；准备任务已受理后允许离开并后台继续，不在整个安装期间禁用，不能继承已卸载页面的状态。两种侧栏模式都验收“返回我的员工 → 切换菜单”和“保存 → 再编辑 → 返回”路径。

宿主未启用 Tailwind preflight，Breadcrumb 显式清除 ol 的编号、margin/padding 及旧 nav 内边距，不通过全局 CSS 重置其他列表。

回归证据见 [角色交互修复记录](role-details-fix-2026-10-26.md)。

## 2026-11-01 讨论内任务整理与等待处理

按 [讨论到任务设计](task-creation-and-review-2026-10-30.md) 的最新覆盖决定执行：整理任务不再弹出第二套聊天；缺项在现有讨论中用声明式表单显示，底部只有一个 ChatComposer。任务建议分层展开，编辑不得突然收缩。授权与补充表单放在任务详情顶部，折叠执行证据不能隐藏或复制待处理控件。压缩输入区与重复固定栏，为正文保留主要空间。

任务详情与列表并排时不显示“返回任务列表”，列表被窄屏详情替换时才保留返回，并恢复原任务键盘焦点。列表不随状态变化重排；明确区分无前置依赖的独立任务与等待验收的依赖任务。详情的前置关系可跳转查看，计划事件注明所属任务与状态。列表显示顺序不能被当作执行依赖。
