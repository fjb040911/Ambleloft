# 精简任务状态栏：DeepSeek 桌面实测

日期：2026-11-06。结论：冲突处理、历史任务查看、真实验收与后续调度、重启恢复均通过。本轮无需修改产品代码。

## 方法与边界

- 使用实际 Electron 桌面应用，通过 Playwright CDP 点击按钮和输入文本，模型为 `deepseek-flash`。没有模拟模型输出或通过 IPC 推进执行、验收状态。
- 独立数据目录 `/tmp/topic-status-deepseek-20261106`，复制上次隔离测试资料，保留两项真实 DeepSeek 历史计划。没有操作用户真实项目、SSH 或 Docker。
- 当前版本禁止生成多个未结束任务，因此在应用启动前，仅对测试副本预置两份旧版遗留冲突草稿。冲突查看、取消结束、确认结束均通过桌面操作；视觉复核时重置这两份人工草稿，再重复处理。未修改任何模型交付或验收记录。
- 新任务为无项目的纯文本分析，明确禁止联网、工具调用和文件读写。只读快照及运行记录用于交叉核验。

## 实际结果

| 场景 | 结果 |
| --- | --- |
| 冲突状态栏 | 仅显示“需处理 / 存在多个未结束任务 / 处理任务冲突”，不展开堆叠列表。 |
| 冲突弹框 | 两份草稿均可查看。取消结束操作保留两份；确认结束其中一份后，弹框收起，状态栏显示剩余草稿及“查看并确认”。 |
| 结束剩余草稿 | 从更多菜单操作，仍须确认；完成后显示“已结束 / 创建下一项任务”，不触发执行。 |
| 历史任务 | 右侧“任务记录”显示真实完成计划和“已结束，未执行”的草稿。打开历史求和计划后仍在原话题内，可看到两个已验收节点并返回讨论。 |
| 新任务引导 | 点击“创建下一项任务”，DeepSeek 先询问新目标，未复用历史数字；随后根据 7+8 的需求生成两个串行节点。 |
| 确认与启动 | “确认并保存计划”后为待执行，两节点执行次数均为 0；再点击状态栏“开始执行”才开始运行。 |
| 首节点交付 | 资料整理员真实输出单独一行 `15`。状态栏“查看交付并验收”直接打开该节点。 |
| 验收后调度 | 同页展示后续任务名称、验算专家、实际状态及“查看任务”。观察到等待调度、准备输入、执行中、待验收，未返回流程图。 |
| 下游交付 | 验算专家真实输出单独一行 `核对通过：7+8=15`。运行记录包含首节点真实验收依赖。 |
| 全部验收 | 两节点均为 `accepted`，计划为 `completed`；状态栏变为已结束，右侧历史从 5 项增至 6 项。 |
| 应用重启 | 已结束状态、创建下一项任务入口和 6 项任务记录均恢复；新完成计划可从历史重新打开，显示已验收 2/2。 |
