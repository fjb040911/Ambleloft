# 讨论到任务、验收与自动调度设计

日期：2026-10-30。范围：协作工作平台的项目空间，沿用概览、讨论、文档与产物、任务、团队与项目。正式文档可选，不以文档采纳作为所有任务的前置条件。

## 用户路径

2026-11-01 增补：讨论入口采用 [主持人协调](discussion-host-2026-11-01.md)。无需预选专家；主持人澄清并委派实际专家，带来源的当前方案进入任务草稿来源快照。模型的 ready 不代替语义检查或用户确认。已创建的任务草稿和正式计划保持固定来源，不因后续讨论被悄悄修改。

自由讨论 → 整理为任务 → 检查信息 → 按需补充 → 确认任务与分工 → 保存计划 / 确认并启动 → 执行 → 在空间内核对交付及证据 → 验收 → 查看后续调度。

2026-11-01 引导衔接补充：最新主持人回复为 `ready` 时，正文下直接展示“下一步：检查任务与分工”和主操作“整理并检查任务”。点击即在当前讨论正文中展开任务引导并检查新草稿，不要求用户再寻找侧栏入口或重复点击提取。该按钮说明使用的模型服务以及发送的讨论、引用资料和专家职责。`ready` 只表示可准备建议，不表示草稿已经存在、专家已经工作或计划已获启动授权。

- 有未完成草稿：显示“继续整理任务”，恢复原来源快照、人工编辑和未发送输入，不自动调用模型覆盖。
- 已有由本讨论创建的计划且无新草稿：显示“查看任务计划”，联动现有任务详情，不重复创建。
- 没有有效参与专家：显示“选择参与专家”，进入“团队与项目”；仍可继续普通讨论。
- 仅最新、未关闭、未归档讨论的 ready 回复提供衔接；后续有新消息时，旧 ready 不能作为新的整理建议。运行期间禁用操作。
- 新草稿整理中展示实际请求状态，保留停止能力；失败保留草稿并可重试。已有草稿的保存、确认和启动规则不变。
- 键盘聚焦下一步按钮时，滚动位置避开固定输入框；返回讨论后焦点回到入口。

讨论右侧“任务”显示本讨论的草稿及相关计划；草稿保留讨论 ID 和固定来源快照，之后的讨论不能悄悄改变已确认任务。可继续原讨论，或在任务整理中以自然语言、声明式表单补充。正文不被强制变成问卷。任务页也提供 AI 引导与手动创建，恢复未完成草稿。

“文档采纳”确认任务依据，“任务验收”确认执行交付，不合并两者。创建计划与启动执行是两次明确动作；“确认并启动”可以将两次操作连起来，但必须先持久化计划。启动失败显示已保存计划及恢复入口，不重复创建。

## 聊天内整理与可处理的等待状态（2026-11-01 覆盖决定）

覆盖此前独立任务整理弹窗的实现：讨论中的“整理并检查任务”留在原聊天正文，任务整理回复和缺项表单按顺序显示。底部沿用 ChatComposer 的位置与组件，并明确本条补充发送给任务整理；同一时刻只有一个消息输入框。不用弹窗包裹第二套聊天，不自动开始执行。

- 动态缺项复用 FormFields；用户也可在底部自然语言补充。表单提交、自然语言补充均调用同一任务草稿检查接口。
- 任务建议按需展开，信息检查通过后展开计划摘要；每个工作包的明细独立展开。人工修改后检查失效，但不得突然收起正在编辑的内容。
- “返回讨论，保留草稿”保存编辑；保存失败留在原处提示。未发送文字、表单回答与同版本候选编辑保留；普通讨论输入草稿不被替换。
- 任务页的独立整理入口也采用内联页面；提供返回任务入口。计划保存与启动仍需明确确认。
- 压缩输入区；模型与发送内容说明收在可展开说明中。专家身份标题随正文滚动，不叠加吸顶栏。任务详情不重复提供固定底部返回栏；验收操作随正文呈现。
- 选中等待中的任务直接定位详情。授权、原生提问、持久化补充表单通过 Conversation 的共享待处理控件呈现在详情顶部；执行证据可折叠，不能把这些操作藏在其中或重复渲染。
- 授权显示实际请求并支持本次批准、拒绝、错误重试，保持原权限边界。表单保留自动保存、校验、投递状态和失败恢复。
- 等待状态尚无具体请求时提供刷新和打开完整任务入口，不要求用户猜测该在哪里输入。尚未完成的任务说明结果待产出，不能把进行中状态说成“交付缺失”。

实现与验证证据：[聊天内整理和任务处理记录](discussion-inline-task-review-2026-11-01.md)。

## 内置 Skill

文件：core/workforce/skills/task-creation-guide/SKILL.md。宿主随 core 打包加载，隐藏于公共技能库之外。普通空间讨论默认注入规则，按用户意图使用信息补充工具；结构化整理使用相同规则和受约束输出 schema。模型输出是建议，不能授予权限或自动运行任务。

必要要素：目标、需求与范围、预期交付、验收条件、验证方法、负责人和执行范围。依赖、非目标、约束、资料按需要填写，截止时间及正式文档不默认必填。模型根据语义判断矛盾、不可验证条件和关键缺口；宿主同时校验结构、有效成员、项目授权、依赖图。字段非空不能代替语义判断。

一次最多三个关键问题，使用现有 FormFields 与动态表单校验。帮助文字属于字段 help，select options 仅 label/value。自然语言和表单答案进入同一份持久化草稿；AI 草稿完整可编辑，人工更改会使原检查失效。信息足够后展示“待确认”，不是“已授权执行”。

引导方法（task-creation-guide-v3 / discussion-host-v2）：先确认目标与业务范围，再从已有信息提出交付、可核验的验收条件及验证方法，根据实际职责和授权项目安排工作。只询问会改变执行的关键业务决定；已回答的问题不重问，技术细节给建议，环境未知项转为有边界的核查任务。每个执行工作包只能有一个真实专家和一个授权项目；本地/远端检查按执行项目拆分并建立依赖。用户最终验收属于交付后的审阅动作，不能虚构“用户”专家或派成人类工作包。回复要说明“已知内容、关键缺口、眼前可做的一步”，不能让用户去查看不存在的任务草稿，也不能把聊天中的“确认”当作启动操作。

结构化整理上下文补齐专家职责、工作方法、交付及技能名称/用途，项目仅提供 ID、名称、本地/SSH 类型和容器环境类型；不附带连接凭据或项目路径。建议保持精简，依赖交付不在每个工作包重复全文。多工作包输出预算为最多 16,384 tokens，仍受用户所选模型的有效上限约束；达到输出上限时不接受截断计划，明确保留草稿并提示缩小首轮范围或调整模型限制。

## 数据与接口

Space state 新增 taskDrafts，兼容旧数据默认空数组。草稿：
- id、spaceId、discussionId、commandId、revision、createdAt、updatedAt
- source：创建草稿时的讨论提示、非思考回复、运行标识和资料版本
- value：name、goal、packages（每项含 verification、constraints）
- messages：补充记录；assessment：summary、missing、question、ready、revision、spaceRevision、ruleVersion
- status：needs-input / ready / created；planId：创建后的计划引用

IPC：createTaskDraft、saveTaskDraft、guideTask、cancelTaskGuide、createGuidedPlan；沿用宿主窗口授权。任务草稿 revision 乐观并发控制，同草稿同时只能一个推理请求；按 requestId 取消，90 秒超时。模型响应必须匹配草稿和空间版本，迟到结果丢弃。用户输入先落盘，失败/停止仍可恢复；进程重启不自动重放推理。

createGuidedPlan 在计划保存同一串行事务内检查评估版本、真实权限和依赖，固化来源并标记草稿已创建。重复确认返回同一个计划。没有正式文档也可创建；引用资料不能自行变为已采纳依据。计划启动使用现有 controlPlan 的宿主授权与依赖调度。

## 原位验收

任务页宽屏列表与详情并排，不显示多余的“返回任务列表”；窄屏详情替换列表时才显示返回入口，返回后焦点回到原任务。概览的待验收入口直接选中对应任务。详情优先呈现实际回复和交付、验收条件与验证方法、文件与命令证据；完整执行过程复用 Conversation，留在当前空间。没有证据明确说明，不用任务目标或预期产物假装实际交付。完整任务外跳仅为可选入口。

验收通过备注可选，记录用户决定、attemptId、结果指纹、时间。未通过必须填写修正原因。验收结果不能绑定到旧 attempt、已变更输出或已变化的本地工作目录。通过后不关闭详情，显示每个下游的真实状态及等待原因。没有下游时显示计划剩余工作或已完成。

运行中计划：验收通过后现有调度器自动检查所有依赖、资料版本、工作目录冲突，再调度符合条件的任务。尚待其他依赖或共享目录时不能显示“已开始”。暂停/停止计划：允许记录验收，不自动恢复。重试被拒绝任务保留历史；暂停计划需用户恢复才运行。当前暂停语义仍是请求停止活跃任务，不改变为“执行完当前”。

**2026-11-01 调度可解释性补充**：列表顺序不代表依赖顺序。无前置依赖的任务可独立调度；同目录执行互斥只限制活跃执行，不把一个任务的待验收状态自动变成所有其他任务的前置条件。列表按保存的工作包顺序展示，状态刷新不重排；需要处理的任务仍可筛选。任务行明确显示“无前置任务”或等待哪些前置验收；详情顶部可查看和跳转前置任务，事件标明任务及状态。正式派发在记录 attempt 的同一事务内再次核对前置验收，不能仅依赖先前计算的可调度列表。见[检查与实施记录](task-dependencies-and-navigation-2026-11-01.md)。

## 验证范围

- 讨论转草稿；资料可选；缺信息→表单/自然语言补充→待确认；手改→重新检查。
- 无权限/成员删除/项目变更/环依赖/空字段/模型伪造 ready 拦截。
- 取消、超时、失败、旧请求返回、并行编辑、重启恢复、重复确认不重复计划。
- 保存不执行；确认并启动；失败保留计划；真实任务输出与证据原位查看。
- 验收通过自动调度、并行与目录锁、其他依赖未验收、暂停不恢复、拒绝需原因、旧结果不可验收。
- 浏览器检查桌面/窄屏/深色、长文本、滚动与键盘操作，保留全局 Tab 吸顶和讨论输入框固定行为。

## 实现边界

模型充分性判断是辅助，不保证需求本身正确；用户必须审阅候选任务。人类验收决定是事实来源，系统不根据“测试通过”文本自行验收。远端或不完整文件扫描沿用现有证据提示，不能伪称本地完整验证。热度、技能推荐 Store 与本功能无新增依赖。

## 系统内置技能与英文优先（2026-10-30 补充）

- 技能与扩展 → 已安装新增“系统内置”分组，与用户安装的技能和扩展分开显示；支持现有搜索和类型筛选。展示名称、用途、生效范围、状态及只读详情。
- 将信息补充、技能大师与任务创建引导统一归类。前两者保留已有启停行为；任务创建引导由宿主按场景加载，无需安装，不提供误导性的启停或普通聊天试用入口。
- `skills.listSystem` 提供宿主管理的只读能力，详情和源码仍复用现有技能预览。它不加入 `skills.list` 的可安装/选择集合，也不会进入普通聊天的 `$` 选择器或专家的技能绑定列表；显示与执行使用同一个打包的 SKILL.md。
- 内置规则以英文维护；用户明确指定的输出语言优先，其次使用宿主提供的界面语言，再参考对话语言，无语言信息时默认英文。结构字段、ID、枚举值和资料引用保持稳定，不翻译。用户手动编辑的文本不擅自改写。
- 任务整理请求显式传入 locale；补充表单标题与校验缺口支持中英文。空间讨论同样注入界面语言。中文显示名称和说明通过现有 Skill 本地化词典提供，未知语言回退英文。
- 需要新版主进程与渲染进程一起生效；更新旧应用时应重启，单独刷新页面不会新增 IPC 方法。旧主进程缺少新只读接口时，仍保留原有技能列表。

## 内置入口层级与专家模型偏好（2026-10-30 补充）

“系统内置”位于已安装内容之后，默认折叠，以次要按钮展开。搜索命中内置能力时自动展开，保留详情与只读约束。

专家配置增加可选 `modelChoice: { providerId, model }`，缺省或清除表示不指定。定义角色页可选择，确认配置页与专家档案可查看。模型与服务一起保存，避免同名模型跨服务混淆。只保存本机标识，不保存凭据。草稿、复制、提交和冻结快照均保留此配置；语义比较包含模型偏好，因此单独调整模型也会生效。

运行规则：
- 新的空间讨论和计划调度：专家指定模型优先；未指定时使用当前任务选定的模型；任务也未选择时使用系统当前默认模型。
- 从专家档案发起普通任务：预选专家模型，用户可在发送前手动覆盖本次任务的选择。
- 已有对话：继续使用已选模型，保留手动切换服务的确认机制；编辑专家配置不会自动迁移历史对话。
- 指定服务或模型已删除：明确失败，请用户重新配置；禁止静默改用其他服务。
- 专家选择弹层同时展示各自模型，并解释讨论模型只作为未指定专家的默认值。AI 辅助定义角色所使用的模型与专家执行模型是两项独立选择，不自动相互覆盖。
