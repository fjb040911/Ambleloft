# 协作计划只读编排图：交互与实施设计 v1

初版：2026-10-26。更新：2026-11-02。状态：**已接入宿主前端，验收与限制见实施记录**。

初版确认只读查看；2026-11-02 用户进一步同意实施流程可视化。本文补充 [协作平台 UI 规范](ui-design.md)，作为实现与验收依据。

> **2026-11-02 覆盖决定**：多工作包计划首次默认“流程图”，单工作包默认列表；两者均可切换，按计划记住本次应用会话中的偏好。界面统一称“流程图”。图展示业务依赖，不使用角色排列代替依赖，不改变调度。详见 [实施与验证记录](plan-graph-delivery-2026-11-02.md)。

## 1. 目标与范围

让用户看清计划的先后依赖、当前进展、阻塞原因和下一步。计划生成后即可预览，执行过程中更新状态，完成后继续保留供回顾。

图中节点代表业务工作包，连线代表工作包依赖；显示宿主计划中的真实 DAG，不展示内部 LangGraph 的 reconcile/dispatch 技术节点，不把专家角色名称当作固定流程。

首版支持查看、缩放、平移、适应窗口、选择节点、突出依赖关系和打开任务详情。**不支持拖动节点改位置、拖线增删依赖、在图中增删任务或修改负责人**。修订计划继续使用现有编辑器及其校验流程；图本身不调用保存、启动、验收或重试接口。

## 2. 入口与页面位置（GV-01）

| 位置 | 行为 |
| --- | --- |
| 项目空间 → 任务 → 某个协作计划 | 每个计划提供“流程图 / 列表”切换；保留计划标题、状态、已验收数量和现有计划操作区。多工作包首次默认流程图，单工作包默认列表；记住用户对该计划的视图偏好 |
| 空间概览 → 当前计划 | 增加“查看流程图”入口，定位该计划并切换图视图；不在概览同时铺开多个大画布 |
| 制定／修订计划 | 为当前候选提供只读依赖预览，标明“未保存预览”；查看不保存、不启动计划，关闭预览保留编辑内容 |
| 已完成／已停止／已归档计划所在空间 | 保留查看能力及最后已记录状态；遵守空间归档的既有只读限制 |

概览中的图入口与现有计划入口应为独立可访问控件，不能在现有整卡按钮内嵌套另一个按钮。图与列表使用相同 planId、packageId 和详情选中状态；切换视图不重复请求执行。

## 3. 节点、连线与状态（GV-02）

每个节点保持紧凑，默认显示任务名称、负责人、所属项目（讨论显示“分析与讨论”）、状态，以及存在时的一条阻塞原因。完整任务、产物、验收要求、引用资料、执行次数和日志放入详情侧栏，避免将长文档塞进图中。

| 情况 | 展示要求 |
| --- | --- |
| 等待调度 | 显示“等待调度”；若上游未验收，说明等待的工作包；宿主提供目录占用等原因时优先展示真实原因 |
| 准备／运行／等待用户输入或授权 | 分别显示真实状态，突出正在推进的节点；等待输入不误标为执行失败 |
| 执行结束待验收 | 显示“待验收”，不能与“已验收”共用完成语义 |
| 已验收 | 显示“已验收”，作为依赖满足的依据 |
| 失败／验收未通过／中断 | 保留各自语义，突出需要处理的节点；中断显示“待核对” |
| 依据过期 | 优先显示“依据已更新”，标出受影响下游，不把旧验收当成有效放行 |
| 整个计划暂停／停止 | 计划级状态单独展示，不将所有节点改写为“暂停”或“失败”；已验收和待处理节点保留事实状态 |

连线从上游指向下游，箭头明确方向；由 `dependencies` 生成，不增加推测关系。上游为有效 accepted 才显示依赖已满足；执行 completed/review 不代表已满足。连线使用克制的主题色、线型或说明，不以持续流动动画表示并未发生的数据传输。

状态文字与图标始终存在，颜色仅辅助区分。状态图例简短；不将“已验收数 / 总数”解释为按工时或工作量计算的完成百分比。

## 4. 查看与详情联动（GV-03）

- 点击节点突出该节点及传递上游、下游，其他分支淡化但仍可识别；点击空白或取消选择恢复全图。
- 同时打开现有任务详情侧栏，复用产物、验收标准、执行证据和完整会话入口；关闭后恢复该节点焦点与画布视角。
- 验收、重试等行为仍由现有详情侧栏的既有动作完成，并遵守权限、状态、结果指纹和确认规则。只读图不增加新的操作路径；用户进入仅查看或归档上下文时不能借详情绕过限制。
- 状态／成员筛选在图中突出匹配节点，保留淡化的依赖上下文并说明“已突出匹配任务”；不能隐藏中间节点后造成上下游已直接连接的错觉。列表继续沿用原筛选方式。
- 支持放大、缩小、适应窗口；拖动画布用于平移，不能拖动节点编辑结构。节点点击与平移手势明确区分，拖动画布结束不误开详情。
- 不自动追踪正在运行的节点或抢走用户视角；提供“定位执行中／待处理”显式操作，多项时按稳定任务顺序循环定位，聚焦后可直接打开详情。

## 5. 布局、视觉与无障碍（GV-04）

默认按依赖层级从左到右排列，无依赖节点位于起点，同层分支纵向排列，合流连线避免穿过节点。布局使用稳定任务顺序与 ID 打破并列；任务无依赖时仍可作为独立节点显示，单任务也支持图视图。

节点尺寸、字体、圆角、边框及状态色复用现有主题 token；外层切换、按钮、提示和侧栏采用现有 shadcn/Base UI 组件。首版不引入装饰性网格、全屏持续动画或大面积彩色节点。

只有任务或依赖拓扑改变、用户主动调整全局字号时重新计算布局。状态、原因、负责人展示文字、语言变化和详情展开不能触发整图重排。长名称在节点内限制行数，完整文本可在焦点提示和详情读取；布局预留稳定状态区高度。

窄窗口保持可平移的有界画布，工具栏可换行但不遮挡节点；保留列表作为同等完整的替代访问方式。图不撑宽整个页面。键盘可依拓扑顺序访问节点，用 Enter 打开详情；缩放/适应窗口有明确可访问名称，侧栏关闭恢复焦点。状态变化采用节制的读屏播报。覆盖中英文、深浅色、390px 窗口及 200% 字号，不以悬停作为唯一获取信息的方式。

## 6. 数据、版本与实现边界（GV-05）

当前代码已有计划列表、依赖、状态和任务详情，图为新增展示层：

| 内容 | 现有来源 |
| --- | --- |
| 计划身份、revision、状态 | `WorkPlan` |
| 节点身份、负责人、项目、依赖 | `WorkPackage.definition` |
| 节点运行状态、原因、过期标记 | `WorkPackage.status / reason / stale` |
| 执行、证据与验收 | `attempts`、验收记录及现有任务详情 |
| 刷新 | 既有空间 snapshot 和 workforce 事件通知 |

展示转换放在可复用的纯适配层，列表与图共用状态文案和优先级，不维护第二份可变任务状态。通过已读取的计划数据与成员/项目索引构建图；不需要新增模型调用、Store 接口或改变 LangGraph 调度器。

计划与状态刷新使用最新完整宿主快照，不能仅以 plan.revision 去重运行更新（运行状态会在同一计划版本内变化）。错误时保留最后可读视图并显示刷新失败，不能伪造继续执行或完成。缺失负责人/项目显示“已移除”，节点仍保留。

本地可存视图模式、缩放、平移和选中节点，这些是 UI 偏好，不写入业务计划、不增加 revision、不生成草稿。节点坐标缓存键包含计划身份与拓扑指纹；刷新运行状态不重置画布。不同计划的选中项与视角不能串用。

修订后图反映当前保存的计划版本并标明版本；候选预览使用编辑器暂存数据，不能混入已保存图的运行状态。新候选或受修改影响节点标记“预览／待重新验证”，不能沿用旧版本“已验收”。若候选有环、缺失依赖或重复 ID，给出校验错误，不绘制误导性的正常 DAG，且不偷偷修改表单。

首版完成后保留的是当前计划版本及最新实际记录，历史 attempt 通过现有详情查看；不承诺未实现的历史时间回放、任意旧版本执行图或跨计划依赖视图。未在宿主明确记录的“可立即运行”等判断不由前端自行保证。

## 7. 实施与验收

建议顺序：图数据适配与状态映射 → 计划内视图切换和画布 → 复用详情联动 → 概览定位及编辑器预览 → 视觉、键盘与真实状态刷新验证。实现使用 React Flow 12.12.0 与 Dagre 3.1.3（MIT），固定版本加入现有依赖；状态文案与列表共用，布局不写入业务数据。

以下为验收索引，执行结果、截图及未覆盖环境见 [2026-11-02 实施记录](plan-graph-delivery-2026-11-02.md)。

| GV-AC-02 | GV-02、GV-05 | 单节点、独立分支、多前置合流和 30 工作包时，节点/连线准确且无遗漏；缺失依赖及环在候选中明确报错 |
