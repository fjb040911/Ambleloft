# 话题与本次任务：单任务串行协作

## 目标与范围

2026-11-06 修订：本方案替代话题列表中的“方案/文档/计划”三个并列入口。用户在一个持续话题里与主持人沟通，逐步建立并执行一个当前任务，不需要先理解多套业务对象。

核心路径：聊天明确目标 → 完善任务草稿 → 确认 → 显式启动 → 检查交付并验收 → 查看实际调度结果。文档是可选参考或产物，不是创建任务的前提。空间顶部的“文档与产物”和“任务”继续提供全局视图。

## 业务定义

- 话题：长期保留的聊天上下文，可以经历多次任务。
- 本次任务：一个顶层工作计划，包括准备中的草稿及该计划的修订草稿。
- 同一话题只能有一个未结束任务。草稿也占用该位置；暂停、失败、待补充、待授权、待验收均不算结束。
- 任务中的步骤仍按依赖调度，独立步骤可以并行。本约束不把工作流中的每个节点强制串行。
- 全部步骤验收通过，或者用户明确停止且执行器已停止后，任务才结束。模型输出完成不等于用户验收通过。
- 未结束时的新想法继续保留在聊天中；主持人说明可以完善当前任务或另开话题。本版不新增队列，不在任务结束后自动执行历史聊天里的请求。
- 用户明确提出下一项任务或点击“创建下一项任务”后，才建立下一份草稿。

## 信息层次与操作

右侧始终是话题列表：最多两行标题和一个任务状态。选中背景与标题字重明确，保留搜索、独立滚动、缩放和吸顶行为。点击话题只打开其聊天，不再切换右侧菜单。

聊天继续复用现有消息、输入框、模型、权限、附件和 @ 专家组件。输入框上方固定一条紧凑的任务状态栏，仅展示状态、可点击的任务名称和一个当前主要操作。桌面保持一行，窄窗允许操作换到第二行；长名称截断并保留完整标题提示，不挤占聊天内容。

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 未生成 | 尚无本次任务 | 整理为任务 |
| 待确认 | 已有未确认草稿，包括信息不足的草稿 | 查看并确认 |
| 待执行 | 已确认保存，尚未启动 | 开始执行 |
| 执行中 | 正在调度或执行步骤 | 查看进度 |
| 已暂停 | 已暂停或正在等待执行器暂停 | 恢复执行；暂停未完成时显示查看进度 |
| 待处理 | 待输入/授权/验收、失败、中断或依据过期 | 待验收显示查看交付并验收；其他显示查看并处理 |
| 已结束 | 已验收完成或明确终止 | 创建下一项任务 |

修订草稿与原任务属于同一个任务。执行仍显示原任务真实状态，并提供“确认修订”；应用修订继续经过版本检查和必要的暂停确认，不自动重启。

“查看交付并验收”直接打开当前话题内的任务节点。复用 PlansPanel、TaskDelivery 和验收结果组件；验收后保留已启动、准备中、未启动及阻塞原因的真实状态，不要求返回流程图验证。讨论 Tab 和右侧列表不变。返回讨论恢复阅读位置、输入内容及焦点。

历史任务移到右侧所属话题的“任务记录 · n”折叠区，不再占用输入框上方的固定空间。已结束计划可打开详情；明确结束的草稿保留记录并标注“已结束，未执行”。跨话题打开历史任务时同步选择所属话题，保留原话题的输入草稿。

暂停计划若有待验收交付，状态栏优先显示“查看交付并验收”；“恢复执行”收进更多菜单。结束草稿和待验收时的确认修订也收进更多菜单。终止草稿仍使用确认弹框；结束修订草稿只放弃这次修订，原计划继续存在。

多个未结束任务的旧数据只显示“需处理 · 存在多个未结束任务”和“处理任务冲突”。点击后用统一弹框列出计划和草稿，提供查看任务、查看草稿、结束草稿入口。计划的暂停、终止和验收仍复用原详情页面。关闭弹框、解决冲突及查看历史不会自动启动或恢复计划；提交失败保留对象、显示错误并允许重试。

主持人的目标、决定及来源作为回复中的可展开内容，不再作为侧栏属性。“整理讨论为文档”放在话题操作菜单，单轮文档收集仍在本轮菜单；文档仍可从聊天引用及全局文档页打开。

## 宿主约束与 API

所有约束在 SpaceService 的串行 change 事务内检查，不能仅靠前端禁用按钮或模型遵守 Skill。

- `core/workforce/topic-task.cjs`：按空间及话题根节点判定任务所有权；共享文档、引用资料、执行记录关联不表示归属本话题。
- `createTaskDraft`：普通重复/并发请求复用当前草稿；`newPlan` 不能绕过未结束任务。原计划修订使用 `basePlanId/basePlanRevision`。已经结束计划的遗留修订不作为下一项任务复用。
- `createGuidedPlan` / `PlanService.save`：确认、应用修订与资料依据确认时再次检查，不允许两个独立任务因竞争同时创建。
- `controlPlan`：启动、恢复、重试检查同话题冲突。旧任务不能在下一项任务已经建立后自行恢复。
- `discardTaskDraft({id, expectedRevision})`：显式结束草稿，记录 `discardedAt` 并提高 revision。保留源数据；结束后不能继续编辑、推理回写或确认该草稿。读取和空间概览排除其待处理状态。
- `discussion-host`：向模型提供 `topicTaskUnfinished`，对不符合约束的 `new-plan/restart-guide` 返回说明并保留当前任务，不调用第二次任务生成。
- 内置 `discussion-host` 与 `task-creation-guide` Skill 同步维护英文规则，输出遵循用户语言。

兼容已有数据：不自动删除旧计划或草稿。若旧版本留下多个未结束任务，标为待处理并提供已有任务入口、结束草稿入口；禁止继续创建或启动冲突任务，用户先处理旧任务。共享文档的其他话题不受影响。

## 保持不变的保护

执行权限、空间成员和项目授权、版本冲突、显式资料采纳、原始交付证据、验收和依赖调度规则继续有效。浏览和普通聊天不启动任务；“确认并启动”与“开始执行”仍是明确执行动作。关闭话题或收起编辑器不等于结束任务。

## 验证范围

- 宿主：并发草稿创建、重复确认、修订版本、暂停/失败/待验收阻断、停止尚未落定、结束后新建、旧任务恢复冲突、结束草稿后迟到响应、旧数据与跨话题隔离。
- 界面：话题只保留一个状态、选中/搜索/键盘、聊天草稿与来源保留、七种状态对应入口、修订与手动表单、验收后实际调度结果、模型和权限、窄屏中英文/深浅主题、吸顶和滚动。
- 测试使用确定性模型及运行时 fixture 验证状态和交互；不把模拟执行结果当成真实模型或远端环境执行结果。
- 状态栏精简回归：54 项浏览器测试通过，覆盖验收与调度结果、任务确认执行、冲突取消/确认/失败重试、跨话题历史、滚动稳定性和消息流。检查 1280px 浅色及 390px 深色截图；桌面状态栏实测 53px，窄窗长标题截断且操作换行。
