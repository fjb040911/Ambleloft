## 2. 阻断验收的业务偏差

### B01：当前采纳依据与最新草稿没有独立存储

对应 A07、A16，D10。

`SpaceService.saveDocument` 只有文档级 `state` 与最新 `revision`，每版没有采纳状态，也没有独立 `adoptedRevision`。`document` 读取历史正文时继承当前文档的 state；`startOne` 通过 documentIds 读取最新版本。

[结构化复现记录](../../../agent-flow/designs/agent-workforce/review/business-adoption-probe-2026-10-25.json)。隔离复现：保存已采纳 v1 → 保存未采纳 v2 → 查询 v1 → 使用该 documentId 发起施工。观察到：

```json
{
  "latestState": "draft",
  "adoptedRevision": null,
  "historicalV1State": "draft",
  "workInput": [{"revision": 2, "body": "unapproved v2"}]
}
```

这不意味着旧正文被删除，也不意味着现有 UI 隐藏了草稿标签；问题是系统不能表示“v2 仍在讨论，但 v1 继续作为有效依据”。在途任务快照已有保护，**新任务选择正确基线**却尚未实现。不能把任意草稿引用等同于正式决定。

修复要求：最新草稿与当前采纳指针独立；版本状态及替代关系可追踪；讨论允许明确选择草稿，施工使用明确的正式输入或记录明确的例外；版本检查覆盖启动/重试，旧结果变更影响可见。完成这些前不能验收“讨论→共同依据→施工”。

### B02：角色管理与单次任务启动尚不能替代协作编排

对应 A03–A08、A11、A17、A26，D01、D06、D16。

`SpaceService.startOne` 启动独立员工会话，施工限定一位员工和一个项目；没有 WorkPackage、DAG、依赖放行、attempt、验收节点、过期结果或统一暂停恢复控制。外部 agent-flow 仍是另一套固定流程，未接成宿主可编辑团队计划。

因此已验证的六次模型讨论只证明角色上下文、所选资料和输出可以串联。不能推导出“用户从顶层启动多模块交付”已完成。用户没有取消这条目标。

### B03：长期员工目前缺少跨任务知识机制

对应 A09、A10，D05–D07。

已有稳定员工配置，但没有原文索引/正式决定查询/授权历史经验检索及撤权传播。Hindsight / Mem0 只有独立小样本试验。员工身份持久化和模型上下文冻结不等于长期记忆。

### B04：角色创建缩减改变了原本业务流程

对应 A18、A19、A22、A23。

实际 RoleEditor 是三步内存表单；没有 RoleDraft 持久模型、引导设计、返回原步骤、员工复制或完整技能确认。离开保护提示放弃填写，不能替代“离开后继续草稿”。用户选择原型后没有要求删除这些功能。

## 4. 本次纠正的文档错误

| 原错误 | 更正 |
| --- | --- |
| 需求/架构仍写“扩展内入口”“不新增 Activebar” | 更新为用户明确的独立协作工作平台与两种宿主模式 |
| 需求仍以 v0.2 技能绑定/启停/必需为准 | 以 D15 和 v0.3 的声明→激活→全局复用替代 |
| 自设计散落员工页，与最新角色库入口矛盾 | 角色库统一承载，其他入口只跳转同一编辑器 |
| 原型四步，宿主 UI 标准却写成三步 | 撤销以实现迁就设计的规范，恢复四步及缺失行为 |
| 概念说明可任意改写并跳全局技能 | 恢复角色模板/AI员工/项目空间三层与首次引导 |
| 文档“一律尚未实施”与后来的真实服务报告矛盾 | 需求写目标，审计写实现状态，历史证据保留时间和范围 |
| Hindsight 首选被读成已最终选定/集成 | 明确只是测试后的首选候选，保留可替换接口 |
| 编排/记忆被称“以后再做”易误读为不在需求中 | 仍属完整目标；分阶段不是用户同意删减 |

## 5. 恢复实施的顺序与验收门槛

这是依据现有需求安排修复顺序，不是新增需要用户逐条确认的方案。

1. **业务依据先正确**：修复 B01，建立 latest/adopted 语义、版本选择和回归用例；这决定 Agent 后续究竟遵循什么。
2. **员工入职闭环**：统一 RoleDraft、四步编辑、AI/手工、草稿恢复、完整确认和激活；同步 Breadcrumb、概念说明、来源弹层与员工操作。
3. **空间交接闭环**：五视图、分步组队、定向讨论、资料读取/提交/采纳；用真实 AI Coding 资料验证结果来源。
4. **顶层交付闭环**：工作包、依赖与 LangGraph 适配、隔离执行、失败恢复、集成验收；不是把模拟计划接上几个按钮。
5. **跨任务复用**：正式决定和来源账本优先；接入可替换记忆服务，补更正/撤权/删除/恢复验证。

逐项交付必须能回答：依据哪条用户决定、哪个需求 ID、入口在哪里、状态如何流转、成功/失败如何验证、还有什么没做。不能再凭构建通过或首页截图宣告整套功能完成。
