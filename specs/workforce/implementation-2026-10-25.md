## 使用入口

重启源码宿主后，选择左侧 ActiveBar 的 **协作工作平台** 独立入口（与项目、任务、扩展并列）。

1. **角色库**：选择产品经理、架构师、Web UI 工程师、集成工程师、文案、教程或测试角色。
2. 按三步设置专业方向、职责、交付、工作方式和技能声明；也可以从“角色库 → 设计角色”自行创建。“我的员工 → 添加员工”统一进入角色库。
3. **仅保存**不会安装；**保存并激活**会准备技能。已安装的全局技能复用，缺失技能进入原有全局技能库。激活不发起模型任务。
4. “交给他一个任务”进入普通任务输入框；发送时自动检查技能。员工标记可移除，普通任务原有行为保持不变。
5. **项目空间**关联已登记的本地 / SSH / Docker 项目，给成员分配项目与职责。无需新目录，不复制或移动源码。
6. 添加空间文档后，勾选本次参考资料和成员发起讨论；或选择一个项目、一位负责人发起施工。打开任务查看宿主中的实际消息、工具与审批。
7. 员工结果可以整理为文档。文档按版本保存，可查看旧版与来源任务。

角色只声明技能：不引入角色专属安装目录，不按角色卸载技能，不给角色增加权限。第三方技能不会被预装冒充；首批模板配套的是本仓库可审计的 8 项 Ambleloft 自有技能，可替换为已安装、本地或 GitHub 技能。

## 技能来源与状态

- 已有技能：选择已登记到宿主全局技能库的技能；停用技能在激活时启用。
- Store：选择固定发布版本，沿用签名、包校验和既有安装器。
- 导入：本地原始技能目录或明确 GitHub 仓库、子目录与 ref。先解析并冻结来源，再加入声明；不能只输入一个模糊名称就静默安装任意仓库。
- 保存、准备中、已激活、需要处理、待恢复是不同状态；逐项展示安装、复用和错误。
- 部分失败保留已成功安装项，重试复用它们；应用重启不重放模型请求。
- 同名而来源不符、已被修改的 Store 技能不会静默覆盖。可在角色中明确选择现有全局技能，或到技能中心处理冲突。
- 移除员工或技能声明，保留全局技能及历史任务。

## 数据与执行

数据库沿用宿主 `Database`，settings 中使用 `workforce.roles.v1` 和 `workforce.spaces.v1`。项目空间只记录现有 Project ID、成员分工及资料引用。角色、空间编辑有 revision 检查。

空间文档由应用管理，正文位于 `<userData>/workforce/documents/<spaceId>/<documentId>/<sha256>.md`，元数据和版本在数据库中。导入技能的审阅副本位于 `<userData>/workforce/sources/`；安装结果进入既有技能库。macOS 默认 userData 沿用 `~/Library/Application Support/Atelier`，显式测试 profile 不受影响。

每个实际任务冻结：员工 ID / 版本、职责与工作方法、技能正文与版本、空间 ID / 分工、所选文档版本 / hash / 正文。角色之后编辑不会改变已存在的对话。暂停和继续沿用冻结快照；若所依赖的全局技能已卸载或停用，给出错误而不偷偷恢复它。

讨论成员各自使用独立对话；结果直接来自宿主 AgentRuntime。施工使用宿主已有本地 / SSH / Docker 路径和权限流程，不借角色获取额外权限。同一项目的协作施工在准备技能之前取得运行期占用，阻止其与其他任务并发；普通任务之间保留既有行为。不同 Project ID 指向同一物理目录的别名冲突尚未处理。

`clientRequestId` 防止同一次请求重复分发；准备阶段进程中断会被标记为中断，不自动重放。角色安装、空间资料保存与模型任务结果分别记录，不把“安装成功”显示成“任务成功”。
