# 项目空间讨论与结论

> 当前协调与路由规则以 [主持人协调设计](discussion-host-2026-11-01.md) 为准：默认主持人、按职责委派、单条 @ 与显式固定专家。本文件后文关于预选成员和截取历史的叙述是早期实现记录。

讨论按首条讨论请求及其 replyTo 链归组；历史数据按同一规则读取，不改写原有运行记录。讨论关闭与文档采纳分开：可关闭没有结论的讨论，也可在采纳后重新打开讨论。关闭前检查相关专家是否仍在运行；已关闭的讨论禁止继续已有运行或发起后续请求。状态在空间数据中持久化，使用 revision 防止并发覆盖。

讨论页右侧按所选讨论展示历史讨论、引用或产生的文档，以及通过相关文档或执行记录关联的计划；顶部文档与任务视图仍覆盖整个空间。通过讨论汇集创建的文档保存讨论来源，历史单个专家产物仍可通过 sourceRunId 识别。文档版本独立支持草稿、待审核、已采纳和已替代；提交审核不改变当前采纳版本，后续编辑另存新版本。用户显式采纳后，原任务继续使用冻结的依据。

当前实现仍是为所选专家分别启动运行；讨论页复用聊天输入组件，专家完整聊天通过现有任务聊天查看。尚未实现统一的多专家聊天运行、主 Agent 自动协调、自动提炼结论或在运行中向整个讨论追加补充；不要将观点汇集描述为 AI 生成结论。继续讨论向专家提供最近 8 轮的截取片段，完整历史仍保留。

2026-10-29 界面修正：讨论页采用独立的消息滚动区与固定输入区，窄窗口将上下文面板折叠。专家的真实运行在讨论中复用任务 Conversation 的同一轮次渲染、过程、表单和授权组件，保留各自的 run ID；完整任务仍可独立打开。讨论的发送仍通过现有空间请求分发，多专家调度和运行中向整个讨论追加补充仍未实现。


2026-10-29 真实窗口交互复查：此前固定区直接显示整段讨论提示词，长标题可把消息区压到零；移动端入口使用 Button 的 important `inline-flex`，覆盖了隐藏样式，桌面网格出现第三个子项，右栏落到下一行。现在标题最多显示两行（完整内容仍在消息内），隐藏逻辑移至无工具类的外层容器，主区和右栏共享明确的单行高度约束；响应式布局按工作台容器宽度切换。

专家、引用资料使用浮层，避免在固定输入区内再套极小的滚动区域。模型选择抽取为普通任务和讨论共同使用的 ModelPicker。继续已有讨论时，未保存过自定义选择则继承该讨论的专家和固定引用；选择仍可手动修改。发送立即显示待提交消息并清空输入，失败可恢复原文且不覆盖新输入；运行中的下一轮草稿和模型选择保留，已启动的专家可停止，然后继续发送。整个讨论运行中的补充调度仍未实现，不能声称已与普通任务所有功能完全一致。

验证：原生 Electron 开发应用中检查长提示词布局、实际打开专家面板、切换模型并恢复原选择；浏览器回归覆盖 390/1280px 长标题、右栏位置、专家选择、引用版本、模型参数、慢请求/失败草稿恢复、新讨论/续轮、运行停止及共享普通聊天。模型调用在回归中为受控模拟，本次未发起真实模型请求。

2026-10-30 间距与专家提及修正：讨论内容区不再叠加通用 Tab 的 24px 顶部内边距和内部上外边距；专家/资料选择与输入框保持 8px 间距。每条专家回复保留“完整任务”入口，“保存为文档草稿”移至专家标题旁的回复操作菜单；本轮的“整理为文档 / 继续讨论”独立成组，窄屏按实际空间换行。整理为文档仍是原文汇集，不代表模型自动提炼结论。

`@` 专家提及复用 ChatComposer 的 ComposerMentions，通过现有 shadcn Base UI Popover + Command 渲染到 Portal；不占输入框高度。支持名称/分工筛选、光标处插入、上下键、Enter/Tab 确认、Escape 关闭、中文输入法保护和最多 8 位参与专家，已选专家显示勾选。没有匹配时 Enter 不发送；普通邮箱不触发选择，中文文字后可直接输入 @。普通任务的 `$` 技能/扩展选择沿用同一实现。

验证：74 项讨论页和普通聊天回归通过；最后的小幅调整后补跑 8 项共享选择器及嵌入聊天测试通过。覆盖 390/800/1280px、打开浮层前后输入框位置/高度不变、键盘选择不触发发送、光标中途插入、中文输入与邮箱、无匹配、保留引用版本、失败恢复与文档操作。TypeScript、Impeccable detector 与 diff whitespace 检查通过。另在真实 Electron 应用的已有长对话中检查顶部间距与 @ 浮层，验证后清空测试输入，未发送真实模型请求。

2026-10-30 页面滚动统一（取代讨论头部折叠方案）：五个 Tab 统一使用空间标题、目标、间距和页面滚动容器，保留 Tab 导航向上滚动时吸顶。不再提供讨论专属的头部折叠、紧凑标题、空间页面菜单或内部消息滚动区；旧折叠偏好不再影响界面。进入讨论时不自动滚到末尾，避免点击 Tab 后头部跳动。

讨论页仅底部输入区吸附在页面底部，消息、讨论标题与其他页面内容沿用整页滚动。输入区在文档流中保留位置，末条消息与操作不会被遮挡；短讨论与空讨论也保持底部输入位置。“回到最新消息”和发送后的跟随均作用于同一页面滚动容器。保留共享 ChatComposer、模型选择、专家提及和草稿；整页滚动恢复仅用于离开空间后返回，不在切换 Tab 时恢复。Tab 吸顶背景不透明，避免正文与导航叠字。

发送按钮的共用样式隔离保留：工作台通用按钮规则不再覆盖 ChatComposer 内部按钮尺寸，发送/发送中/停止继续由共享组件控制。验证：41 项讨论、空间及共享输入框浏览器回归通过，覆盖 390/800/1280px 的标题位置一致、Tab 吸顶、输入区固定、末条消息可读、草稿/滚动恢复和浅深色空讨论；TypeScript、Impeccable detector 与 diff whitespace 检查通过。检查了对应浏览器截图，未发起真实模型请求。

2026-10-30 Tab 切换滚动修正：滚动位置以空间为单位保存，不再按 Tab 保存或读取整页偏移。切换时，尚未吸顶则保持当前标题及导航位置；已经吸顶则保持导航贴顶，将新面板起点放在导航下方，不继承上一页的深层内容偏移。位置调整在布局阶段完成；面板区最小高度使用实际滚动视口高度并随窗口调整，短内容不再把吸顶栏推回原处。退出中的 inert 面板立即退出布局，避免旧内容临时占高。旧版按 Tab 保存的数据不再读取。

### 2026-10-30 讨论输入框补齐共享操作

- 讨论输入框直接复用普通任务的 `ComposerControls`，左下方提供“＋ / 权限模式”，右侧保留模型选择；窄窗口权限仅显示图标。
- “＋”支持添加文件、文件夹和本轮指定技能，使用相同的选择、移除与错误提示组件。技能声明不改写专家配置。
- 所选附件、技能和权限传入本轮每位参与专家的运行请求。未选择权限时仍为默认权限；完全访问沿用现有确认弹框；无效权限由服务端拒绝。
- 运行中附件和权限不可修改，模型选择仍可用于下一轮。发送失败保留输入和附件技能；发送成功清理本轮附件技能。重新打开页面恢复默认权限。

## 2026-11-01：删除讨论

讨论标题右侧增加“讨论操作 → 删除讨论…”，复用 shadcn DropdownMenu 与宿主 ConfirmationProvider。打开、关闭以及没有结构化元数据的旧讨论都可删除；无需先关闭。活动中的主持人、专家或正在准备的空间请求完成/停止前不能删除，前后端均拦截。归档空间沿用只读要求，先恢复再操作。

`discussionLifecycle` 增加 `action: delete`，沿 replyTo 找到根讨论，在单次串行写入中检查 revision、移除同空间的完整讨论链。只保存最小删除标识（根 ID、轮次 ID、spaceId、revision、updatedAt），拦截迟到重发或原专家任务继续执行，重启不复活已删讨论。删除其他空间不能清除这些标识；删除所属空间时一并清理。

原专家任务、已保存文档及其版本、任务草稿、计划和固定来源快照不级联删除。保留文档可以继续独立修订；不能伪造新文档来自已经删除的讨论。任务详情显示“来源讨论已删除”，不再提供失效跳转。尚未发送的消息保留，删除后回到新讨论、清空旧接收路由与回复目标。删除失败保持原内容和错误反馈，可重试；确认弹窗默认焦点为取消。

案例更新见 [设备维修工单 · 协作试验](repair-ticket-collaboration-scenario-2026-11-01.md)，首条消息只表达目标、边界及验收需求，不点名专家。
