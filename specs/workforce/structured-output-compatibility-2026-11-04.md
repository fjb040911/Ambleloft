# 结构化模型输出兼容与保护

日期：2026-11-04。替代 `invalid-output-2026-11-04.md` 中按 DeepSeek 名称选择 JSON 模式的策略。

## 范围与调用链

主持人、任务创建与关系引导、计划建议、角色引导与建议、技能匹配均使用 `core/automation/provider.cjs`。这些调用只产生待校验数据，不执行工具。业务层继续检查成员与项目身份、权限、依赖关系、草稿版本、用户确认，再保存或调度。

流程：选择协议及输出格式 → 请求模型 → 检查完整响应 → 解析 JSON → 完整 Schema 校验 → 业务校验 → 原有确认及保存流程。

普通 Agent 的工具调用循环不属于本次结构化输出重试范围。协议自动模式可以使用已验证的协议记录；工具能力仍需独立验证。

## 输出格式

- 首选原生 Schema 输出，其次 JSON 模式，最后提示词约束。
- 两种协议分别写入 Chat Completions 的 `response_format` 和 Responses 的 `text.format`，不按模型品牌选择。
- 原生 strict Schema 使用可移植子集；可选字段不会被擅自改成必填或 nullable，不可表达的结构使用 JSON 或提示词模式。
- 服务端约束可以省略不兼容的边界关键字，但本地 AJV 始终校验原始完整 Schema，包括字段、类型、必填项、数量、长度及额外字段约束。不自动转换类型、补默认值或删除额外字段。
- 接受纯 JSON 或单个完整 JSON 代码块。不从说明文字中截取对象，不猜测修补引号，不接收截断结果。
- 接口接受 Schema 参数并输出合格数据，不代表已证明服务端实施了严格约束，因此本地校验不可省略。

## 统一预算和失败分类

一次调用最多 4 次 HTTP 请求，协议切换、格式降级和内容修正共用预算。最多一次协议切换、一次内容或 Schema 修正；调用方较短的截止时间仍然有效。共享适配器默认 180 秒；主持人讨论及其调用的计划生成显式禁用总时限，使用连续 300 秒无新文本的静默超时。持续输出的推理或回复会重置静默计时，SSE 元数据不会；格式降级和内容修正不会自行重置静默计时。

格式降级仅处理明确的格式或 Schema 不支持错误；Schema 专属错误不会把整个模型的 Schema 能力标为不支持。自动协议切换需要明确的协议拒绝；设置页固定测试另外允许用另一种协议验证未知 404，业务请求不会对未知 404 盲目换协议。

认证失败、限流、模型不存在、拒绝回答、输出上限、断流、网络异常、业务校验失败均不触发内容修正或盲目格式降级。用户取消后不发送下一次请求，不应用返回结果。

重试限定在推理阶段，不重跑创建计划、保存草稿、启动节点等业务操作。修正反馈仅含 Schema 路径与关键字，不回传失败输出中的私有内容。错误诊断仅保存阶段、原因、HTTP 状态、尝试数、协议、格式等元信息。

## 能力记录

能力保存在原 providers 设置记录中，兼容没有能力字段的旧配置。作用域包括端点、模型、配置协议、思考设置、输出限制及凭据指纹；实际协议和流式/非流式另行区分。

缓存保存实际验证成功的格式以及被明确拒绝的格式。一次 JSON 成功不会推导 Schema 不支持。记录有效期 30 天，重复使用同一结果不延长有效期或反复写数据库。重新测试从最高可表达格式开始。

修改相关配置或凭据使旧记录失效；改显示名称保留记录。异步返回的旧配置结果不能覆盖新配置。缓存写入失败不否定已经通过校验的推理结果。

## 设置页

“测试已保存端点”发送固定的 `{status: "ok", count: 2}` 合成请求，最多 4 次、总计 45 秒，不发送项目内容。成功显示当前模型、协议及验证格式，并明确这是非流式结构化输出检查，不代表其他模型、流式或工具能力通过。更改未保存配置后隐藏旧成功状态。

## 验证证据

- 适配器测试覆盖 Chat Completions / Responses，使用 GLM、Kimi、GPT 示例模型名验证格式选择与品牌无关。这是协议模拟测试，不是对应厂商真实服务认证。
- 覆盖完整本地校验、共享预算、Schema 专属降级、拒绝/认证/限流/模型错误、取消、缓存持久化与过期、配置变化和迟到写入。
- 打包测试从临时目录加载随应用发布的 AJV 及其依赖，确认本地校验不依赖开发环境。
- 两个已配置端点的真实固定测试：DeepSeek / deepseek-flash 拒绝 Schema 格式后 JSON 成功；pro6000 / DeepSeek-v4-flash 接受 Schema 请求并返回合格数据。结果在隔离内存设置中验证持久化读回，未修改用户配置。
- DeepSeek 真实隔离业务回归：生成计划、解释节点、修改节点、查询状态全部通过，约 14.9 / 10.5 / 17.3 / 9.7 秒。没有启动 Agent 或部署。
- 设置页回归覆盖结果展示、验证范围、配置编辑后隐藏旧结果，以及认证失败反馈。

复现命令：`electron scripts/probes/structured-output-capabilities-live.cjs` 和 `electron scripts/probes/discussion-plan-workflow-live.cjs --deepseek-only`。两者需明确允许使用已配置服务；只处理合成测试数据。后端修改需要重启桌面应用的主进程才能生效。
