# Windows 更新发布

从 v0.9.6 起，Windows 安装包直接订阅 `fjb040911/Ambleloft` 的已发布预览版和普通 Release。无需用户运行配置脚本。Mac 和开发环境的自动检查仍关闭。

应用启动约 10 秒后检查，此后每 15 分钟检查；设置中可手动检查或关闭自动检查。发现新版本出现蓝色下载图标。点击后进行差分下载并校验，随后在空闲时自动重启。运行中的任务、终端和未保存输入会阻止安装；用户可取消下载或取消等待重启。等待超过 10 分钟会取消自动重启，保留已下载安装包。单独开启“自动下载”不会授权自动重启。

## 发布一个版本

1. 更新 package.json 和 package-lock.json 中的版本号，提交并推送对应 `vX.Y.Z` 标签。
2. 运行 GitHub Actions 的 **Publish Windows update**，填入标签。工作流构建 Windows x64 预览包、测试并执行发布工具。
3. 或者在本机运行 `npm run dist:win`，再运行 `npm run release:win -- release 可选的发布说明文件`。

发布工具先验证安装包 SHA-512、文件大小和 blockmap，再创建草稿并上传 EXE、blockmap、latest.yml、ZIP（若有）及 SHA256SUMS.txt。只有远端附件的大小和 SHA-256 全部匹配，才公开 Release。失败会保留草稿；不会覆盖已发布的版本。不要绕过工具发布缺少 Windows 更新附件的新 Release。

版本使用递增的纯数字 X.Y.Z；GitHub 的 Pre-release 标记不影响本渠道接收更新。内置引擎保持不变时会优先复用缓存，只下载变动块；缓存缺失或差分失败自动回退全量。签名正式发布工作流及其签名要求保持不变，本工作流提供未签名 Windows 预览包。

## 旧版本

原版 v0.9.5 及之前的已发布安装包排除了 GitHub 预览版，这个限制不能通过新元数据改变。用户手动安装 v0.9.6 一次后，后续按上述流程发布的版本可直接从应用内更新。不再要求使用旧的 0.9.4 → 0.9.5 配置脚本。
