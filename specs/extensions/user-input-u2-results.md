# U2 聊天框补充输入与继续操作

日期：2026-10-14。接入正式 Conversation / ChatComposer；动态补充表单、请求服务和内置 Skill 仍按 U3–U8 推进。

## 行为

- 宿主提供 inputs API 时，运行中可以 Enter 或发送按钮提交普通补充文字；停止是独立按钮，发送期间仍可使用。
- 发送期间输入框保持可编辑。持久接受后只清理未被再次编辑的本次草稿；失败保留原文。同一文字失败重试沿用 clientMutationId，轮次在重试前结束也不改走新消息入口。
- 运行中的补充只支持文字，不隐式忽略附件或技能。已有附件/技能时给出明确提示，下一轮普通发送继续使用原配置链路。
- 停止后主按钮明确标记“发送并继续”。旧 queued 内容默认不选择；仅显式选择的内容通过 generation CAS 放行，其余 held 保留。发送新补充时也不默认放行旧内容。
- 输入框上方显示持久投递状态：排队、发送、暂停、失败、待核实。unknown 不提供自动重发；失败原文可复制后修改发送。
- 同一聊天从 input:event 刷新状态；异步过期读取不覆盖较新的快照。旧宿主未提供 inputs API 时保留原本轮结束后发送行为。

## 视觉与可访问性

按 Taste-skill 的保留式优化原则，沿用现有字体、主题、导航和圆角语言；以 shadcn/ui 的 Alert、Collapsible、Field、Checkbox、Badge、Button、InputGroup 组合实现。

- 正常送达只显示轻量状态行，不增加一张常驻大卡片。
- 暂停提示突出原因与下一步；投递明细默认折叠，展开后限制列表高度，长正文允许换行和滚动。
- 继续所选内容为明确的主操作，未勾选时禁用。输入框的暂停态发送按钮显示文字“发送并继续”。
- 状态不只用颜色表达；复选框有正文标签，折叠和按钮支持键盘，沿用主题 token，无装饰性持续动画。
- 新文案提供中文、英文词典。

## 验证及边界

新增浏览器用例覆盖发送期间编辑不丢、失败幂等重试、选择性继续、发送新补充不释放旧内容、发送期间仍可停止；同时回归现有 Composer 的模型选择、权限、草稿、IME 和键盘行为。使用正式 React 页面与模拟 preload 数据；不是对真实模型服务的端到端发行验收。

本轮未改 SDK/CLI 公共 API。U3 下一步实现持久 InputRequest、草稿版本控制、答案与队列原子提交，再接入动态表单和统一待补充区。当前投递状态区不是完整表单 dock。

最终结果：新增补充输入浏览器用例 5/5 通过；既有 Composer 用例 8/8 通过；`npx tsc --noEmit`、`git diff --check` 通过。已检查 760×700 浅色与深色截图，暂停操作和输入框保持可见。
