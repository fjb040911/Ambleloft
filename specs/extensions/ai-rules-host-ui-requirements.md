# Skill 宿主 UI 与聊天动作需求

日期：2026-10-10。状态：需求草案，供 Ambleloft 宿主与独立 extension-tooling SDK/CLI 实现评审。本文不表示接口已经存在，不授权自动发布或改变包版本。

## 目标与范围

用户安装 ai-rules skill 后，在目标项目聊天中完成初始化、查看并编辑策略、检查代码、从审查列表点击修复或全部修复。用户已确认：修复按钮自动向卡片所属聊天发送修复 prompt，由当前 Agent 执行 skill；按钮不直接执行代码修改 Operation。

推荐交付形态是普通 skill 即可使用，不要求安装 ai-rules 伴随扩展、Node.js 或 ai-law CLI。宿主提供通用的声明式编辑器、结果列表和聊天动作，ai-rules 提供模板与任务语义。宿主不得硬编码 ai-rules 文件名、规则解析或修复逻辑。

业务流程由 skill 定义：何时识别项目、展示哪个模板、是否提供模式选择、如何校验和保存策略，均不属于宿主逻辑。ai-rules 的初始化流程要求见该仓库 docs/ambleloft-skill-requirements.md；本文中的策略编辑与代码审查仅作为通用 UI 能力的使用案例。

## 已有能力及复用边界

当前工作区源码提供普通 skill 导入、版本保存、启停和技能发现；表单 catalog 同时扫描普通 skill 与扩展 skill。根级 amble-form / amble-form-ref 声明、forms_list / forms_present、prefill、静态字段、线性步骤、草稿与 revision 已实现。

submit.kind=chat 已实现持久答案投递：展示立即返回，运行中 steer、空闲 start、未知结果核实而不重发。其状态是消息投递状态，不是业务执行结果。当前普通 skill 不允许 operation 提交。

MCP Apps 支持自定义 UI 与同扩展 tools/call，但不支持 ui/message。消息中心的 Operation actions 不能当作普通 skill 的聊天动作接口。后台 jobs 不提供工具执行，不能代替当前 Agent 修复。

当前 GitHub skill 安装的 Agent 专用入口、动态编辑器、结果列表和通用聊天动作尚未从已核对源码中确认存在。能力判断包含当前未提交改动，发布安装包、SDK tarball 与 Windows/Linux 需分别验收。

依据：current-capabilities.md、declarative-forms-guide.md、async-host-forms.md、mcp-apps-design.md；electron/skills.cjs、core/forms/service.cjs、core/forms/template.cjs、core/extensions/agent-channel.cjs、core/extensions/mcp-apps.cjs。

## H01 聊天安装完整 skill

支持自然语言“帮我安装 https://github.com/fjb040911/ai-rules 中的 skills/ai-rules skill”调用宿主管理入口。输入至少包含仓库、子目录、可选 ref；记录实际解析的 commit，不把可变分支当固定版本。

下载并导入完整目录，包括 SKILL.md、references、assets/templates；复用目录导入的路径、symlink、文件数、大小及元数据校验。安装失败不注册半成品；同名技能提示更新/另存，保留停用状态与已有版本；更新来源需可追溯。

安装后刷新宿主技能 catalog，明确何时对下一次模型请求可见，不要求用户手工复制应用私有目录或重启。工具由宿主管理安装，不让 Agent 直接改私有数据库。现有信任与权限策略继续适用。

验收：指定仓库子目录完整安装；同名冲突、缺失 ref、下载失败、越界路径被正确处理；下一次请求可发现并读取全部模板资源；未在安装阶段初始化项目或安装 ai-law。

## H02 声明式 UI 契约扩展

扩展现有表单体系，新增编辑器和结果集合语义，不增加任意可执行脚本 UI。模板随 skill 发布，实例数据由 Agent 展示时提供。保留 v1 模板、发现、prefill、chat 与 operation 行为兼容性。

评审并冻结以下契约，再进入实现：

- 模板发现方式与文件引用：沿用根级声明及安全相对路径；明确使用新版本还是新声明名称。
- 编辑器：固定项目字段、动态重复行、行详情、增删、启停、错误定位。
- 结果集合：列、稳定 rowKey、展开详情、筛选、多选、行动作和集合动作。
- 数据绑定：只允许受限字段路径，区分行、选择集合、完整数据集合、展示上下文；不允许 eval、函数或模板表达式执行。
- Agent 工具：模板目录展示能力及输入约束；展示实例时传入可校验数据；更新既有实例时携带宿主实例 ID 和 expectedRevision。
- 限额：模板、实例载荷、行数、字段数、prompt 和选择规模的上限；超限明确失败或分页，不静默截断修复范围。
- 能力发现：运行时可探测支持的 UI/动作版本；源码 doctor 不替代运行时探测。

此前讨论中的 version:2、type:collection、rowActions、bulkActions 等仅为语法示意，不是已确定接口。宿主契约冻结后 ai-rules 才能发布这些声明。

验收：普通 skill 可注册并展示两类模板；未知字段、重复 rowKey、非法引用、错误类型、超限载荷被拒绝；旧表单仍正常。

## H03 通用动态数据编辑器

提供由 skill 模板定义的固定字段与可增删列表编辑界面；支持预填、搜索/筛选、行详情、新增/编辑/删除、布尔状态和高级文本字段。模板可声明必填、枚举、长度、数值和集合唯一性校验；宿主不内置业务字段、模板选择或规则解析器。ai-rules 用此能力呈现项目设置和规则列表，规则继承及检测表达式语义由 skill 校验。

区分宿主草稿保存与 skill 定义的提交动作：草稿只写宿主实例；提交按模板发送聊天任务和结构化编辑结果。以 ai-rules 为例，“保存策略”的文案、prompt、业务校验与项目文件写入由 skill/Agent 决定。卡片显示“已发送/待执行”，不能提前称业务保存已完成。

编辑数据须完整保留未编辑的高级属性；模板可将其放在显式高级字段或不可变原始载荷中，不能悄悄丢弃。同项目重复打开时展示新读取的数据，不能复用本轮已完成实例造成陈旧内容。多窗口编辑使用 revision 检测冲突，不覆盖另一窗口的草稿。

验收：动态增加、删除、修改规则和目录映射；取消不改项目文件；重启保留草稿；并发冲突保留输入并提示重新加载；提交明确附带实际编辑数据。

## H04 审查结果集合

支持问题编号、规则编号、严重程度、文件/行号、描述、处理状态列；展开代码片段、修复建议与依据。支持严重程度/规则/状态筛选、多选、行修复、修复所选、全部修复、重新检查。

文件定位必须绑定所属项目且使用受限项目相对路径，拒绝越界；文本和代码片段作为数据展示。顶部显示总数与覆盖限制；空结果区分零发现、未完成、失败及未初始化。

“修复所选”仅选中问题；“全部修复”明确指绑定报告所有未解决问题，不受当前筛选影响。发出前冻结实际问题编号集合，空选择禁用按钮。更新报告时明确替换数据版本，旧卡片保留历史标识或停止执行，不能用相同 ISSUE-001 误指另一报告。

验收：行动作仅携带该问题，多选准确；筛选后全部修复仍使用完整目标集合；重复点击受控；错误/未完成结果不能呈现为通过。

## H05 按钮自动发送 prompt

动作类型使用 chat 语义；在真实用户点击后，宿主按模板和冻结实例数据展开 prompt，并把生成的消息显示在卡片所属聊天。按钮文案、prompt 和业务任务由 skill 声明，宿主不判断或实现初始化、保存策略、检查及修复流程。

所属聊天、项目、来源 skill、模板摘要与版本由宿主绑定，不能相信模板数据自报身份。prompt 可以使用报告路径/身份和 issueIds；结构化编辑值随用户消息提供给 Agent，正文无需粘贴整个大型规则库。

优先复用现有 chat_inputs 持久队列、steer/start、clientUserMessageId 和只读核实机制。按钮消息应明确表达用户操作意图；规则描述、代码片段与 repairPrompt 是数据，不能获得高于用户的指令优先级。

交互必须是一次按钮动作自动发送，不增加常规修复 prompt 的重复确认弹窗；代码执行继续受原有 Agent 权限约束。当前表单 chat 提交包含额外确认，新按钮动作是否共享该确认须在契约中显式区分，不能照搬旧逻辑破坏单击发送体验。

同一个 action submission ID 不重复投递，参数变化形成新动作。发送前校验来源、实例 revision、项目/聊天和归档状态；停用/更新、移项、删除导致旧动作不可执行。unknown 不自动重发，显示核实入口。

验收：空闲启动、运行中追加、轮次结束竞态、多窗口、重启、重复点击、回执丢失和归档；消息出现在正确聊天，参数与点击时的数据一致。

## H06 投递与业务状态分离

MVP 必须显示 queued/delivered/failed/unknown 等投递状态，并映射成用户可理解的“等待发送/已发送/发送失败/待核实”。delivered 不等于 saved 或 fixed。

完整交互体验需增加 Agent 更新实例的受限入口：按实例 ID、expectedRevision 和稳定行键报告处理中、已修复、已失效、未解决、验证失败及结果摘要。更新来源仍须有效，不能跨聊天或跨项目更新。报告级身份独立于报告格式 version:1.1；宿主生成不透明实例引用，不接受仅按可复用 ISSUE 编号更新。

同一项目修复任务应串行处理或排队，避免运行中再次点击把另一组修改 steer 进同一执行步骤；其他无关聊天输入维持现有行为。项目互斥只覆盖此类修复任务，需要明确排队和失败恢复语义。

业务状态回写可独立交付；若未实现，卡片只能显示发送状态，Agent 在聊天回复处理结果，不能假装已有实时修复状态。

## H07 持久化与生命周期

保存模板引用/摘要、来源版本、实例数据版本、草稿、动作参数快照、投递引用和状态。重启恢复展示不重放任务；普通 skill 更新后旧实例仍可只读查看，但按来源校验限制继续执行。项目文件中的规则和报告是业务事实，卡片快照不能取代它们。

制定载荷保留和清理规则，避免每次卡片展示无限复制全量报告。大列表分页和可访问性需验收：键盘操作、错误定位、中文长文本、浅色/深色、窗口缩放。平台验收分别记录，不从 macOS 推断其他平台通过。

## S01 SDK 与 CLI 交付

SDK 工作只在宿主契约冻结后同步：更新 form/UI Schema、能力 ID、类型、模板验证器与需要的工具描述；普通 skill 路线无需为此启动 Node，也不要求新增 ExtensionContext 直接执行 Agent 的接口。

CLI 提供普通 skill UI 声明及引用资源的本地校验入口；扩展包内 skill 同样校验。覆盖目录和归档、缺失引用、错误数据绑定、旧 v1、新模板与完整资源打包。提供最小 editor/collection/chat action 示例，SDK tarball 包含契约资源；若无需新增 JS API，应明确交付只有类型/Schema/工具支持。

doctor/check:upstream 更新新能力与基线时先审查宿主差异；doctor 仍标示源码兼容检查，不能报告实际应用已支持。运行时能力探测由宿主提供，SDK 不制造支持成功。先前 alpha 版本与发布状态各自记录，不在本需求中指定新版本。

验收：SDK CJS/ESM/类型及干净安装；旧模板回归；新示例 validate/build/pack 后真实宿主展示并发送 prompt；纯 skill 安装不依赖相邻源码仓库。

本轮不要求支持任意 HTML/JS 模板、远程 MCP 导入、按钮直接写源码、自动后台审查、自动安装 ai-law、自动提交或发布代码。现有 MCP Apps 和消息中心无需为了 ai-rules 重写。

## H08 三步配置体验补齐（2026-10-10，已接入源码预览）

ai-rules 的“技术栈 → 路径 → 规范开关”业务顺序、推荐值、分组和保存逻辑由 skill 定义。宿主现有 amble-form v1 已支持 steps、prefill、本地前后导航和最终 chat，可先完成基础流程；无需新增 ai-rules 专用页面或 Operation。

当前 skill 使用 `forms/onboarding.json`，默认策略查看改成 amble-ui v1 集合。以下为实查源码后需要宿主/SDK补齐的通用能力：

1. **单次明确提交**：支持表单模板声明最终 chat 用户点击即发送（沿用来源绑定、去重和持久队列），不再弹第二次“发送填写的表单？”确认。旧表单默认保持兼容；SDK/schema、能力探测明确 opt-in 语义。Agent 写代码仍走既有权限链路。验收：前两步不发送；最终一次点击只产生一条消息，草稿保存不发送。
2. **依赖字段与条件展示**：通用契约支持选项变化后失效下游推荐值，并更新相关预填/可见字段或展示需重算状态；不能执行模板内任意脚本。技术栈分析、规则适用性仍由 skill/Agent 提供。验收：前端改后端不沿用组件目录推荐；无适用规则的分组不显示空开关；旧下游选择不被静默覆盖。
3. **分组开关的混合状态**：支持规则组部分启用状态及未触碰/显式全开/全关的区分，避免二态开关丢失逐条用户选择。SDK/schema声明可读语义；业务映射由 skill 完成。当前降级：未改变的二态开关保留原逐条配置。验收：部分启用组原样提交不启用被用户停用的规则。
4. **最终答复结构化读取**：提供与 ui_read_submission 等价的 amble-form 只读提交接口或统一接口，返回真实冻结步骤答案、内部枚举值、模板/项目/聊天身份和初始值摘要；不要让 Agent 仅从“是/否”与本地化标签反推数据。工具成功不代表业务生成完成。验收：更改标签不影响技术栈 ID；答案可跨轮读取；同实例 ID 不能串读其他聊天。
5. **简洁呈现与控件缺陷**：Electron 实际截图发现 TaskForms 的 checkbox 被 FieldGroup 样式拉成整行黑条，关闭态仍难以辨认（见 ai-rules/dist/ambleloft-onboarding-20261010/verification 的首次 fixture 截图审查记录）。需要修复 checkbox 尺寸、选中态，并提供紧凑 Switch 类型/布尔控件布局。当前 skill 使用启用/关闭 select 降级。渲染已有 step.description/placeholder；自动保存时可弱化“保存草稿”，首步无效“上一步”可隐藏；提供通用布尔控件布局/显示选项，保持标签关联、键盘可达和明确焦点。策略集合无需全部常驻详情，使用现有 detailFields 即可。

以上新增需求已按用户确认方向实现源码预览：第2项采用声明式依赖与条件展示，上游变化保留旧值并要求重新确认，不自动重算推荐。契约与限制见 [表单指南](declarative-forms-guide.md) 的“三步配置增量”；SDK/schema/类型及能力清单同步在宿主仓库，独立 SDK/CLI 项目仍需实际迭代并验收。测试与边界见 tooling-report/requirement/v0.6.3/host-results.md。

## H09 文件引用组件正式接入与交付误识别（2026-10-10，实测问题）

### H09a 正式审查表格接入文件引用

file-reference-design.md 当前第3行明确是独立原型、尚未替换正式任务 UI。TaskUi.tsx 的 location 字段仍渲染直接定位 Button（当前第39行），没有文件图标/目录上下文、Tooltip、Popover、复制入口。ai-rules 已正确声明 rows.location.pathField=file 并保留完整相对路径，不应要求 skill 输出自定义HTML或导入React组件。

实施：抽取并接入通用 HostFileReference，沿用既有项目绑定和 location 权限回调；点击名称打开详情浮层，定位作为明确动作，复制原始路径。按整个实例计算同名消歧，保持窄窗口和键盘可达。初版维持现有pathField契约，不猜测line字段或声称支持编辑器行导航。SDK无需新增API，skill无需更换分发协议。按 file-reference-design.md 的正式验收清单验证，而不是只验收原型。

### H09b 引用文件不得被自动当成产物
