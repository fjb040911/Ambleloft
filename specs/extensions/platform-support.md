# 跨平台架构与发行要求

状态：已确认产品约束。Windows、macOS、Linux 都是正式发行目标，Extension 核心能力必须在三平台提供一致契约。当前 macOS 开发机的验证结果只代表已执行证据，不能把其他平台从范围中删除。具体最低系统版本、CPU 架构、Linux 发行版及显示环境矩阵需在发行基线中另行明确，不在此虚构支持版本。

## 通用核心与平台适配

`core/extensions` 负责 manifest、Operation、权限、确认、生命周期状态机、身份和存储语义；不得依赖 macOS 路径、应用包结构、系统命令或窗口行为。公共 manifest/SDK/RPC 不暴露平台专用句柄，也不要求扩展按系统实现三份业务逻辑。纯 JS/静态页面扩展应能使用同一包运行。

Electron 适配层统一封装进程、窗口、页面来源、用户目录、系统凭据、外链及退出行为。确有差异时通过内部能力检测和适配实现，不把平台分支散布到 OperationRouter 或授权逻辑。相同输入和授权在三平台产生相同业务结果、错误码及取消/结果未知语义；平台能力不可用时明确失败，不通过降低隔离或权限检查回退。

utilityProcess 和 WebContentsView 是待三平台验收的实现选择，不是 macOS 专用架构。若某目标平台不满足页面隔离、可信确认或进程生命周期要求，应修复适配或重新评审通用容器路线，不能直接把扩展功能从该平台发行中移除。

## 必须隔离的平台差异

| 边界 | 统一要求 | 必测差异 |
| --- | --- | --- |
| 包路径与文件系统 | 清单路径使用包根相对 POSIX 表示，统一规范化后转换为本机路径 | Windows 盘符/UNC/设备名/ADS/尾随点和空格；大小写冲突；Unicode 文件名；symlink/junction/reparse point；Linux 权限位 |
| 运行时与原生依赖 | 使用应用自带 Node/Helper，不依赖用户 PATH Node、全局 npm 或安装时下载 | 每个 OS/arch 的 Electron/Node/ABI/N-API、依赖二进制、可执行权限、ASAR 路径与解包资源 |
| 引擎与内部 MCP | 固定引擎版本、相同工具契约、每次执行上下文隔离 | `.exe`、参数转义、stdio/管道、退出与取消、无 POSIX shell/信号假设 |
| 页面与可信确认 | 相同来源绑定、专用 preload、主 frame 校验、modal 出现时隐藏扩展 view | Windows DPI、macOS Retina、多屏缩放、Linux X11/Wayland、窗口管理器、焦点/键盘与原生合成遮挡 |
| 用户数据与凭据 | 使用宿主目录服务和系统凭据适配；加密不可用时明确失败 | 各平台 userData 路径、密钥后端、Linux 桌面密钥服务缺失；禁止明文回退 |
| 应用生命周期 | 显式退出清理后台、窗口关闭与后台生命周期分开定义 | macOS 关闭最后窗口后存活、Windows/Linux 退出策略、子进程树、文件占用、原子替换与卸载重试 |
| 分发与更新 | 相同契约版本与权限策略，平台产物有明确版本和架构 | Windows 安装/签名、macOS 签名/公证、Linux 包与运行依赖；包更新期间文件锁和恢复 |

可移植包的路径校验不能只使用当前开发系统的 `path.isAbsolute` 或 `realpath` 推断其他平台安全。A1 目录预检只是基础校验，A3 必须补齐跨平台文件名、完整归档条目及安装事务规则。携带原生模块的扩展需要明确目标 OS/arch 和实测兼容信息；对应清单字段另行评审，当前不擅自扩大 API。

## 发行与验收门槛

- A0 的引擎新建/恢复/旧线程、utilityProcess、页面来源及原生遮挡探针必须在三平台的原生环境运行；交叉打包或 mock 通过不等于运行通过。
- A1 通用契约与条件测试在三平台执行；加入平台路径反例。后续所有平台适配均保留相同的核心契约测试。
- A3/A4 覆盖安装更新、文件占用、进程崩溃、取消、停用和退出；A5 覆盖 DPI/缩放/焦点/弹层及多窗口；A6 覆盖双模型协议和内部 MCP 隔离。
- A8 每个平台都执行真实发行产物的干净环境 smoke：没有系统 Node/npm、没有仓库 node_modules，验证内置引擎、校验器 bundle、preload、页面资源和包内依赖。
- CI 应包含 Windows、macOS、Linux 原生 runner 的单元/契约和打包 smoke 矩阵；桌面合成、凭据后端和安装器另设真实桌面/系统验收，不能用 headless 单测替代。
- 某平台未通过时标记该平台阻塞和具体缺口。不得宣称三平台支持，也不得据此永久缩减已确认发行目标。三平台正式发行完成必须有三平台证据。
