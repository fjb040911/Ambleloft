# Extension 首版范围与已确认决策

更新日期：2026-10-01。状态：公开设计草案；范围决策已确认，具体接口尚待评审，不代表功能已经实现。

本文是扩展平台首版的公开范围基线，与链接的专题设计共同记录已确认决策，不依赖内部讨论资料。待定字段和参数不构成稳定 API；实现前需要补齐契约、代码迁移映射及验收清单。

## 2026-10-01 增量范围

新增 MCP Apps 协议适配层与任务内隔离 UI，复用 Extension Operation、权限和确认路由。首版仅支持包内独立 HTML、inline 卡片和同扩展工具调用；不承诺兼容任意远程 MCP 服务或 ChatGPT 专有接口。详见 [MCP Apps 设计](./mcp-apps-design.md)。下方早期里程碑的对话组件排除项，已由本增量对该有限范围修订。

## 声明式表单设计增量

已确认采用 YAML 定义确定性表单，宿主统一以 shadcn/ui 渲染；模型负责选择与预填，线性多步骤使用稳定实例关联。“上一步”只修改草稿，不自动撤销已执行业务操作。具体设计见 [声明式表单与多步骤流程](./declarative-forms-design.md)。基础链路已实现，具体支持范围以[当前能力表](current-capabilities.md)和[表单指南](declarative-forms-guide.md)为准，不追溯改变 M1 的历史验收结果。

## 基础原则

- Windows、macOS、Linux 均为正式发行目标；扩展公共契约、核心能力与授权语义保持一致。平台差异由内部适配层承接，不以单平台探针结果缩减发行范围。具体架构约束和验收矩阵见 [跨平台要求](./platform-support.md)。

- 只有一套 Extension 体系，优先建立自己的生态，不承诺兼容 Codex 或 VSCode 的插件包和 API。
- `extension.json` 是扩展身份、版本和能力的唯一主清单；`package.json` 管理 npm 开发和依赖，不要求 `plugin.json`。
- Skills、工具、Hooks、页面和后台按需组合，UI 命令不自动成为模型工具。
- 静态入口注册与代码激活分离；需要运行时处理的贡献按需激活，通知后台可在应用启动完成后激活。具体事件与清单字段待接口评审。
- 清单支持多语言及受限条件表达式；可见性、可调用性和资源授权分别校验，条件不是授权，不执行任意表达式脚本。
- 用户信任后运行 Node 扩展，宿主 API 授权限制核心资源；完整 Node 不是系统沙箱。代码信任与项目资源授权分开。
- 同一用户配置（profile）下跨窗口共享应用级后台，不同配置的资源与授权隔离。profile 不等于扩展服务中的业务账号。
- Extension 入口展示扩展列表，选择后打开扩展自定义操作首页；设置中的管理页面负责配置、启停与授权。无 UI 扩展无需空页面。
- 业务对象从扩展页面关联本地项目，一个项目可关联多个业务任务，关系和业务归属由扩展决定，不向内置创建任务表单注入 PM 专有字段。
- 轻量事件仅携带事件与资源标识；扩展决定是否读取、生成摘要或同步。完整轮次完成指工具循环与最终回复结束并持久化，不是单次工具返回或流片段结束。
- 扩展自行管理 WebSocket、MQTT 等连接，平台提供消息中心，不自动合并不同扩展的连接。

## 1. 里程碑

首版为 M1＋M2，分阶段验收。双导航布局独立推进，不阻塞扩展平台验收；先用现有布局落地扩展列表和操作页面。

- M1：本地安装包、清单校验、扩展列表、独立页面、Node 后台、统一 Operation、页面及 Agent 调用、基本授权、禁用和卸载。交付最小示例扩展及打包校验工具。
- M2：轻量 Hook、按需授权读取、后台提示词作业、消息中心、多窗口共享后台及恢复。
- 原 M1 交付不包含：扩展市场、自动升级、跨扩展调用、宿主标准表单组件、内置表单字段注入、远程 Extension Host。标准表单已按上方增量进入后续设计，其他排除项保持不变。

对话内表单采用扩展声明、宿主渲染，Agent 选择和预填，用户明确提交。具体契约提案见 [声明式表单设计](./declarative-forms-design.md)，与原消息模块分开施工。

## 2. 运行与页面

每个已激活的 Node 扩展使用独立进程，同一应用、同一用户配置下跨窗口共享。首版仅有应用级后台实例，项目通过显式 ID 和授权上下文区分。纯 Skills 或远端 MCP 扩展不因此额外启动 Node 后台。独立进程是故障隔离，不是系统安全沙箱；脱离管理的子进程不在自动清理保证内。

M1 正式页面来自扩展包内的静态 Web 构建产物；开发模式允许本地开发服务器与热更新。业务功能通过消息桥调用 Node Operation，凭据在后台管理。页面跳转到外部站点后不继承宿主 API 权限。正式运行的自带 Web Server、远程页面嵌入暂缓，是否进入 M2 仍待评审。

## 3. Operation

M1 所有 Operation 在清单中声明 ID、说明、输入/输出结构、调用范围，后台激活时绑定 handler；不支持运行时新增任意操作。明确声明 page、agent 或两者，默认不暴露，猜测 ID 不能绕过可见性检查。

操作接收明确参数，不直接弹业务表单收集参数；页面或 Agent 先完成业务交互，再调用操作。宿主审批可以在调用过程中发生。页面和 Agent 共用业务契约、实现及资源授权规则。

M1 执行端为 Node handler。已有 MCP 功能保持可用，不强制迁移；宿主 Operation 直接绑定 MCP 工具后续再做。扩展后台可以自行调用 MCP 服务。

采用异步请求，一次调用返回结构化结果或明确错误。宿主设置超时上限并传递取消信号，扩展配合停止。页面关闭取消该页面未完成调用；Agent 取消执行时取消其未完成操作；应用级连接继续运行。取消等待不代表业务回滚，连接中断可能产生结果未知状态。宿主不自动重试有副作用的操作，单次操作超时不直接杀死整个后台。

M1 不做通用持久任务系统；长任务可以返回业务服务任务 ID，由查询操作跟踪。宿主持久作业属于 M2。

## 4. 资源授权

按能力声明，按具体项目授权，默认不包括其他项目或未来创建项目。安装时确认代码信任，首次使用相关能力时申请资源授权，已有有效授权不重复询问。每次页面或 Agent 调用都经宿主检查，入口可见、清单声明、点击行为不能代替授权。

后台缺少授权时返回状态，不自行弹窗。项目选择器可以合并展示关联意图与本次所需权限，由用户一次确认。撤权后拒绝后续访问并尽力取消进行中的宿主任务；已交付给扩展的数据不能保证收回。首版暂不提供“所有项目”批量授权。授权边界是宿主 API，不是完整 Node 的文件和网络沙箱。

### 4.1 操作确认策略（已确认）

资源授权回答“允许访问什么”，操作确认回答“是否现在执行”；两者分别校验。采用按风险及调用来源决定的确认策略，不对所有写操作重复弹窗，也不让开发者自行决定免确认。

- 读取操作在已有资源授权时无需重复确认。
- 写操作默认确认。普通可撤销修改可由用户对“具体扩展＋具体操作＋项目”开启免确认；开发者只声明操作性质，宿主按规则决定是否具备免确认资格。
- 对外发送/发布、破坏性操作、批量修改及权限变更保留逐次确认，不因普通操作免确认设置而豁免。
- 页面可用宿主控制的提交确认组件，一次明确操作同时完成业务提交与平台确认；不在此之后再次弹相同确认。
- 确认绑定本次操作及实际参数，参数变化则失效。扩展声称“用户已点击”不构成确认依据。
- Agent 发起普通写操作首次确认，后续仅在用户已开启对应免确认策略时可直接执行。重要操作逐次确认。

页面和 Agent 均受资源授权及平台规则限制。开发者风险声明不是可信行为证明，也不是对完整 Node 代码的强制沙箱。

## 5. 安装与开发

支持本地安装包和开发目录。正式包包含清单、编译代码、页面及依赖；安装不执行脚本、不临时下载依赖。先校验并展示来源和能力，再由用户信任启用，导入不执行代码。

同一扩展只启用一个版本，支持手动新版本替换：先校验新包，替换前停止旧实例，不做自动更新。新包校验失败保持旧版本运行；替换时暂停新调用、停止旧实例、保留旧安装包后切换。新增权限不自动授予，依赖这些权限的能力等待用户授权。新版本启动失败保留诊断，提供手动恢复旧代码版本入口。M1 不提供自动数据迁移或自动回滚；扩展开发者负责数据兼容，恢复旧代码不承诺恢复旧数据格式，宿主必须明确提示兼容风险。开发模式支持后台重新加载与页面开发服务器；同 ID 调试暂时停用当前配置内正式实例，不覆盖正式安装，结束调试可恢复。

禁用保留配置与数据；卸载默认保留扩展数据，提供显式清除选项。

## 6. M2 Hook 投递与默认策略

订阅在清单声明，按用户授权项目范围投递。事件只带标识和资源引用，扩展决定是否按需读取正文以及如何处理。

- 至少一次投递，同一 eventId 可以重复到达，扩展负责业务幂等。
- handler 成功返回即确认；错误、超时或进程退出进入有限重试。延后处理时扩展必须先持久化事件再确认，不能只放入内存。
- 应用重启或扩展崩溃后恢复此前已启用且已授权订阅的未确认事件。
- 主动禁用或撤权停止投递，清除对应待处理事件；重新启用不自动补历史。尚未安装或启用的扩展不积累事件。
- 可靠交付不代表摘要生成或业务服务同步成功；声明式提示词作业另有宿主状态管理。

| 参数/情形 | 已确认默认策略 |
| --- | --- |
| handler 超时 | 30 秒，用于接收事件，不等待模型摘要完成 |
| 自动重试 | 首次失败后最多重试 5 次，指数退避加随机间隔 |
| 待投递保留 | 最长 7 天，并限制每扩展队列容量 |
| 耗尽或过期 | 转入失败记录，允许手动重试或丢弃 |
| 容量耗尽 | 报告投递缺口，不静默丢弃、不阻塞主聊天 |
| 顺序 | 同一聊天按事件顺序尝试投递；重试可能重复，不以到达顺序代替版本判断 |

数值是首版默认配置，不是永久不变的公开协议。具体退避间隔、容量数值、失败记录保留期以及重试是否阻塞后续事件仍待确定。手动重试不能绕过当前授权；事件过期进入失败记录不代表正文仍可读取。

事件保留不承诺历史正文保留同样长时间；版本不可用时明确返回，由扩展决定处理。禁止静默读取最新版本代替事件版本。

## 7. M2 后台提示词作业

首版提供无工具的后台提示词作业：扩展提交提示词、授权输入和输出 schema，宿主返回作业 ID，管理模型调用、并发、输入输出限制和预算。用户可暂停扩展自动作业。模型使用用户允许的配置，扩展不能经宿主 API 读取模型密钥。

作业独立执行，不向源聊天插入消息、不阻塞后续轮次。业务操作由扩展收到结果后执行，不在模型作业内运行工具循环。此限制针对宿主管理的作业，不是限制完整 Node 扩展调用自己的业务服务。

状态和结果持久化，结果通知可重复投递但不能因此重复生成。只有通过输出结构校验并持久化的结果才算成功；格式错误返回失败原因，不隐式发起额外模型调用修复格式。

| 中断状态 | 已确认恢复规则 |
| --- | --- |
| 尚未发出模型请求 | 重新检查授权和预算后继续排队 |
| 结果已持久化 | 交付已有结果，不再调用模型 |
| 请求已发出但无持久化结果 | 标记结果未知；提供方支持时先查询，否则不自动重新生成 |

结果未知时通知扩展，由用户决定是否重试；首版不默认允许扩展自行重试该作业。重试可能重复计费，不能把无响应当作提供方未执行。后续可评审用户按扩展授权自动重试的策略。状态机必须覆盖请求发出与本地落盘之间的故障窗口，不能据此承诺模型调用恰好一次。

## 8. M2 消息中心

详细结论已集中至 [消息中心设计](./message-center-design.md)，作为本节的配套决策记录；继续评审时在该文档维护细节，避免两份完整规则产生分歧。

- 统一承载宿主和扩展的关注信息，采用纯文本消息与声明式动作；复杂业务进入扩展页面。
- 本地 Profile 无需登录；平台账号与扩展业务账号可选且独立。消息、配置与会话按明确的范围隔离，同一 Profile 多窗口共享后台。
- `设置 > 消息通知` 按 Profile + 扩展控制接收与静音，覆盖该扩展的全部账号；拒收不停止扩展业务后台。
- 阅读、业务处理、有效性、清除与动作执行分别建模。更新不重新提醒，清除不改变业务，终态不能恢复为待办。
- 动作通过声明的命令异步调用，先落盘后派发，统一校验授权和版本；长任务返回已受理，结果未知不自动重放。
- 后续结果回报与所附消息更新原子提交，支持幂等、崩溃恢复和账号切换隔离。
- 已确认 31 项必过验收标准，均待执行；SDK 签名、存储结构、限额与保留策略仍待评审，不能视为实现完成。

## 9. 应用退出与扩展故障恢复

关闭单个窗口不停止应用级后台。最后一个窗口关闭遵循应用自身退出规则，主进程仍运行时后台继续工作；用户退出应用则停止扩展，不安装额外系统常驻服务。应用退出后不保证实时推送，重启后的业务补拉由扩展负责。

扩展意外退出时采用退避，最多自动恢复 3 次，持续失败后暂停并提供手动恢复入口；稳定运行一段时间后重置计数，具体时间参数待定。主动禁用不触发自动重启，按既定规则清理待投递事件。故障暂停与用户主动禁用必须区分，不能把恢复耗尽误作用户主动清除队列的请求。

- Operation 在崩溃后不自动重放，已经发出的业务写入可能结果未知。
- Hook 未确认事件依照第 6 节恢复投递。
- 页面显示后台恢复状态，恢复后可重新操作，不自动重放旧点击。
- 提示词作业按第 7 节状态恢复，不因扩展重启而再次调用模型。

## 10. 首版核心资源 API 范围

| 阶段 | 能力 | 边界 |
| --- | --- | --- |
| M1 | 项目选择器 | 用户主动选择，不向扩展枚举全部未授权项目 |
| M1 | 已授权项目基本信息 | 稳定 ID、名称、说明；工作目录路径单独授权 |
| M1 | 创建和打开项目聊天 | 创建与执行分开，不因创建而自动调用模型 |
| M1 | 扩展专属存储、配置及凭据存储 | 按扩展和用户配置隔离 |
| M2 | Agent 事件订阅及对应轮次读取 | 按项目授权，读取明确版本和字段 |
| M2 | 提示词作业与通知 | 遵守作业预算、授权与消息中心契约 |

首版暂不开放修改或删除既有聊天、修改核心项目配置、读取完整历史及任意文件的通用宿主 API。扩展自动启动主 Agent 执行暂缓；创建聊天由用户检查后发起执行。上述限制是宿主 API 范围，不改变受信任 Node 自身的系统访问边界。

### 10.1 稳定聊天身份（已确认）

扩展创建的聊天从草稿、首次发送到后续继续执行，始终保持同一个 `conversationId`。“复制为新聊天”生成新的 `conversationId`，原聊天引用保持不变。

`conversationId` 是宿主提供给扩展的稳定业务引用，不等于草稿或 run 的内部记录 ID，也不等于模型引擎的 threadId/turnId。内部记录转换不能要求扩展重新关联；创建聊天仍不自动启动 Agent 执行。

具体 identity 表结构与旧数据迁移方式属于实现设计，不改变上述已确认行为。
