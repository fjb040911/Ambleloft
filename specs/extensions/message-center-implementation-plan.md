# 消息中心开发推进计划

状态：保留最初分阶段规划。2026-10-08 消息动作与认证已实现部分源码预览，当前支持范围见 message-actions-auth-guide.md；下列“尚需”描述初始审计，不是当前缺口清单。

依据：[消息中心设计](./message-center-design.md)。对话内表单见[未来方向](./conversation-interactions-direction.md)，不进入本轮范围。

## 现有代码初步核对

- `core/extensions/persistence.cjs` 已有扩展安装、授权、私有数据表与本地 profile 标识，可沿用数据库事务基础；尚需消息、账号会话、执行和幂等记录的专用设计。
- `core/extensions/operations.cjs` 已有调用来源、授权与审批、进程调用和 onDispatch 标记；现有标记不能直接当成持久派发日志，需要补齐数据库阶段与崩溃恢复。
- `core/extensions/manifest.cjs` 当前命令面向 openHome；不能把讨论中的业务命令处理函数当成现有已实现能力。需要设计命令到 Operation 的映射，校验器与路由共同变更。
- `core/extensions/bootstrap.cjs` 已有后台绑定通道、配置和存储 API。消息与账号 SDK 应通过受绑定通道扩展，不开放任意 IPC。

以上是局部代码核对，不替代完整迁移审计。

## 建议阶段

| 阶段 | 交付 | 验证重点 |
| --- | --- | --- |
| N0 契约与迁移设计 | 精确 SDK 类型、清单差异、错误结果、表结构与事务、默认限额和保留策略 | 覆盖全部已确认规则；未决事项审阅确认 |
| N1 持久消息核心 | Profile/来源/账号隔离，发布更新撤回，偏好、阅读清除、去重、过期与版本 | MSG-P、MSG-S 的核心存储场景及并发测试 |
| N2 动作执行与恢复 | 命令映射、授权、执行快照、持久派发、原子回报及恢复 | MSG-A、MSG-T 和进程崩溃故障注入 |
| N3 页面与设置 | Apple 风格消息列表/详情、过滤、角标、批量操作、设置中的来源开关 | 多窗口同步、无障碍、真实操作流程 |
| N4 SDK、Demo 与集成验收 | 真实扩展发布消息、按钮执行、账号切换和恢复示例，开发文档 | 31 项验收逐项记录，真实进程/页面验证及既有功能回归 |

各阶段可以逐步实现，但不能以本地无账号 Demo 代替账号隔离验收。系统通知不是首版验收前置条件；Hook、提示词作业与对话内表单不因此自动纳入范围。

## N0 首轮待评审建议

先收敛消息发布和管理接口：publish、getByEventKey、update、withdraw、getPreferences。建议仅由 Node 后台调用；页面通过声明操作访问后台。重复发布不覆盖内容，拒收返回正常业务结果，更新使用预期版本；精确返回联合类型和错误码需给出可评审草案。

随后补齐账号/会话句柄、reportActionResult 和未结束执行查询，以及命令到 Operation 的映射。完成契约和存储评审后进入 N1，不将未确认的签名直接变成公共 SDK。
