# U6 正式任务待补充区

日期：2026-10-14。U6 实现完成，主进程在装配 InputRequests 后启用内部 inputToolsEnabled。开发模式需完整重启 Electron 后台；页面热更新不会增加旧后台的工具或事务支持。新建执行上下文才发现新工具，已有活动上下文不动态改写工具列表。

## 页面与交互

- 正式 Conversation 的 conversation-dock 接入 SupplementalInputDock，位于聊天输入框上方、消息滚动区之外。沿用现有配色，使用 shadcn/ui Card、Badge、Button、NativeSelect、Alert、AlertDialog、Collapsible 与 U4 的共享字段组件。
- 显示来源类别、表单标题、填写原因、保存状态与待办数量。多个表单和原生问题共享选择入口，只展示当前项，隐藏项保持编辑实例。新请求不自动抢焦点。
- 稍后填写仅折叠，不取消、不提交、不更改请求状态；继续填写恢复当前内容。提交成功后折叠剩余待办，避免自动展开下一份表单挤压聊天。
- 面板限高，字段区滚动，提交按钮独立保留；浅色、暗色与 390px 窄窗口验证。权限卡仍使用原来的授权区与操作语义。
- 历史中显示只读补充记录，pending 可定位回待补充区；已提交记录可展开查看答案，不创建第二份编辑表单。显示“已提交”仅表示答案已接受，实际投递状态仍由投递面板负责。
- 原生问题保留 QuestionQueue、Questionnaire 和 answerRun 专用通道。切换待办不丢原生输入；未改为 steer，也不宣称其旧 RPC 可跨进程恢复。

## 草稿与提交

- 首次编辑立即请求 beginEdit，输入先保存在窗口内缓冲；后续短延迟自动保存。窗口内控制器独立于表单挂载，折叠/切换不会丢失缓冲或生成第二次提交；已保存草稿仍以宿主持久记录为准，不写浏览器存储。
- 自动保存期间继续允许打字和保持焦点；提交期间冻结该表单字段，普通聊天输入框仍可使用。服务端字段错误定位到首个错误字段。
- 命令使用 revision CAS 和稳定 clientMutationId。回执丢失时重试同一命令，先取得原回执再保存新输入。冲突不自动覆盖本地填写；用户明确确认放弃未保存输入后，才载入最新版本。
- input:action 的错误现在经 preload 保留 code/message/fields，前端能区分冲突、校验和暂停，不再依赖 Electron 的错误字符串。
- submit 新增可选 `resume:{expectedPolicyGeneration}`。同一事务校验版本、恢复 policy、保留旧队列为 held、写入冻结答案并入队新回答。只放行本次回答；旧队列仍由已有选择恢复入口处理。校验失败或配额失败整笔回滚，不暗中恢复任务。
- 宿主界面文案跟随应用语言，模板标题/标签按其原有快照显示，业务值不翻译。

## 后续边界

U7 负责取消/替换、文字关联提案的确认/拒绝、原生 resolved 与终止清理，以及恢复诊断。本阶段不提供尚未实现的取消/替换按钮，不自动接受文字关联提案；原表单仍可继续填写提交。U8 内置 Skill 引导、U9 真实引擎及发行验收保持后续计划。

SDK 没有新增 Node 方法。此处 resume 为宿主 renderer 内部提交参数，不能与扩展业务授权或 API 提交混淆。
