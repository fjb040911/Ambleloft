# 平台认证与扩展身份：设计草案

> 2026-10-08 实现更新：消息操作与扩展企业认证已有源码预览链路。当前可调用接口与明确限制以 [消息按钮与认证接入规范](message-actions-auth-guide.md) 为准。以下设计中的账号选择器、账号消息与其他未来能力不代表本次已实现。

状态：本文保留长期架构目标。OIDC 与现行 SDK 接口已实现源码预览，具体以现行接入规范为准；全局账号选择器、刷新令牌及账号消息仍未实现。

## 已确认边界

- 平台先支持可配置的企业身份提供方，不自建账号密码系统。
- 本地 Profile 始终存在，未登录可使用本地 Agent 能力和本地扩展；模型服务与业务服务仍各自要求必要认证。
- 平台账号、扩展业务账号和 Profile 分离。平台登录/退出不迁移本地数据或切换全部扩展后台。
- 扩展独立登录的业务会话不因平台退出而默认退出；依赖平台身份的授权须失效。
- 消息的宿主身份、来源和账号上下文不能从页面或扩展提交的任意字段采信。登记业务账号不等于平台验证了该身份。

## 已确认的身份共享与账号连接交互

### 身份共享边界

- 平台身份默认私有，不向全部扩展广播用户资料、账号列表或 Token。安装、启动或接收消息不自动授予身份访问。
- 身份资料访问按扩展及允许字段授权；业务访问按目标服务和权限范围授权。平台不向扩展的任意 HTTP 请求自动添加认证头。
- 同一企业的扩展可以在兼容时复用登录会话，但各自获得明确授权和适用于目标服务的访问能力，不能随意复用一份 Token。
- 不同公司的服务默认独立连接账号；只有明确的身份联合信任才能复用身份，不能因用户登录了 A 公司就将身份发给 B 公司。
- accountScope 只是宿主隔离和关联数据的标识，不是凭据，不能向业务服务器证明用户身份。
- 以上约束适用于宿主接口。可信 Node 扩展不是操作系统级沙箱，不能据此承诺恶意本机代码之间的秘密隔离。

### 连接时机与账号选择器

1. 扩展后台启动时，有有效授权则恢复连接；否则标记未连接，不自动弹出登录窗口。
2. 用户打开扩展或使用需要认证的功能时展示“连接账号”入口；用户主动点击后，由宿主打开统一账号选择器。未连接不阻止不依赖认证的本地功能。
3. 选择器只展示适用于该身份提供方、目标服务和租户要求的账号。候选项由宿主依据受认可的配置筛选，扩展声明本身不能证明兼容性。
4. 选择前扩展不得枚举全部账号；选择并授权后，仅获得被允许的账号信息与会话能力。已有账号也可能需要补充授权或再次验证，不能保证无感登录。
5. 提供“使用其他账号登录”，进入身份提供方登录流程，不在扩展自定义表单中收集企业密码。服务器地址和企业连接配置属于独立高级入口，不能等同于输入新账号。
6. 账号选择与授权流程明确展示请求扩展、目标服务、选定账号及所需权限。API Token 服务采用独立的凭据连接方式，不伪装成已验证的企业登录。

账号断开、授权撤回及过期后的恢复仍遵守 Profile/业务账号独立与消息会话隔离规则。具体组件、认证清单字段与 SDK 签名未冻结。

## 已确认的“设置 > 账号”结构

采用连接列表加新增／编辑表单，不同时展示多份完整配置表单。

| 区域 | 内容与操作 |
| --- | --- |
| 已连接账号 | 登录状态、重新登录、退出，以及已授权的扩展 |
| 企业连接 | 多条配置列表，新增、编辑、删除，以及默认连接选择 |

企业连接配置、已登录账号、扩展连接授权是不同对象。一条配置可对应多个账号，一个账号可授权多个兼容扩展，服务权限仍分别管理。首版支持多条企业配置、一个默认连接，以及同一配置下多个账号。

新增与编辑使用同一套表单，基础内容包括显示名称、issuer、clientId、必要的租户限制，以及高级配置和“验证配置”操作；精确字段与校验规则待契约设计。密码和 Token 不填在配置表单中。回调地址由宿主展示，管理员据此在身份平台登记；配置验证不等于用户登录或扩展授权成功。

默认连接仅用于优先展示，不自动登录、授权或使不兼容账号进入扩展选择器。相同 issuer 不保证能共用 clientId，服务要求独立应用注册时使用独立配置，不自动合并。

## 已确认的认证 SDK 职责

SDK 提供类型与宿主调用封装；登录界面、凭据存储、刷新和权限检查由宿主实现。扩展声明业务需求、处理未连接状态，服务端独立验证访问凭据与业务权限。

| 接口草案 | 已确认职责 |
| --- | --- |
| auth.getSession(connectionId) | 静默获取本扩展已有授权的会话，无可用会话返回 null，不枚举全部账号 |
| auth.connect(connectionId) | 用户主动触发，宿主校验交互上下文并打开账号选择器；不能信任扩展自报 userInitiated |
| auth.disconnect(sessionId) | 断开本扩展连接，不默认退出其他扩展共享的企业登录会话 |
| auth.onDidChangeSession(listener) | 仅通知本扩展可访问会话的变化 |
| auth.request(sessionId, request) | 宿主为已声明、已授权的目标服务获取适用凭据并代发认证请求 |

接口名称、参数与错误结构仍为草案，须与 SDK 项目共同冻结。会话默认只返回受限引用和获准的账号资料，不包含原始 Token。认证请求建议以 resource 引用及 path/method 等描述，不能接受任意目标 URL，也不能把认证头跟随重定向发送到其他站点；完整目标约束待技术设计。

优先交付“会话管理＋宿主代发认证请求”。WebSocket、第三方客户端库等需要直接持有访问凭据的场景另行评审受限访问令牌接口，不直接开放平台刷新令牌。

## 建议的协议与职责

首版建议支持 OIDC 企业身份提供方，通过 Discovery 读取授权、Token 和签名密钥端点，并校验 issuer 一致性。桌面端使用系统浏览器进行 Authorization Code + PKCE，不在扩展 Web 页面中收集企业密码，不把客户端 secret 内置为桌面应用可保密的凭据。依据 [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html) 与 [OIDC Discovery](https://openid.net/specs/openid-connect-discovery-1_0.html)。

身份使用 issuer + subject 关联，并在需要时记录经过验证的租户上下文；不以邮箱、昵称合并身份。验证签名、issuer、audience、有效期及本次请求 nonce；state/PKCE 与单次登录尝试绑定。依据 [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)。具体协议库、回调方式及支持的提供方矩阵待评审。

| 层 | 建议职责 |
| --- | --- |
| Identity Provider 配置 | issuer、clientId、允许的 scope、回调与租户限制；由宿主或部署配置管理 |
| Authentication Service | 登录尝试、回调校验、会话、刷新、退出与失效广播 |
| 安全凭据存储 | 加密保存需要持久化的刷新凭据；不进入页面、日志、聊天或普通配置 |
| 身份投影 | UI 与扩展按需要获得账号标识和展示信息，不自动获取 Token |
| 扩展授权 | 独立决定扩展能否使用平台身份、调用哪个服务；登录不等于授权扩展 |
| 消息服务 | 消费已绑定的账号/会话上下文，不承担密码或 Token 校验 |

## 分阶段建议

1. 先定义宿主认证服务、账号引用与会话失效契约，继续实现 local 范围的消息功能。
2. 接入一个可配置的 OIDC 提供方，以本地测试 IdP 验证登录、刷新、退出和并发回调；没有真实企业端点时不虚构验证成功。
3. 接入账号范围消息和扩展平台身份授权，验证账号切换、旧会话拒绝、在途结算及重启恢复。

平台退出先使本地会话不可用，再按提供方能力尝试撤销/退出；不能因远端撤销失败继续允许本地身份使用。账号消息隐藏不代表删除历史或撤销已发出的远端业务。

## 待评审决策

- 已确认：首版仅支持 OIDC；SAML 经企业身份网关转换，暂不支持设备授权流。
- 已确认：系统浏览器、Authorization Code + PKCE、本机 loopback 回调；具体提供方对动态端口的兼容性仍需验证。
- 企业配置表单的编辑权限、是否另支持部署导入，以及多账号下默认账号、并发会话和删除配置时的处理；多条配置和每配置多账号已确认。
- 企业业务服务如何获得面向自身 audience 的授权，不能把一个服务的 Token 默认转交所有扩展。
- 无法安全持久化凭据时的交互、离线状态、刷新并发控制与失效事件模型。
- 账号选择器具体实现、最小用户信息字段、凭据代理接口及迁移策略；交互原则已确认。

## 实现推进

已实现内部单次 loopback 登录尝试模块（随机 state/nonce、S256 PKCE、回调校验、超时与取消）。尚未接入 Discovery、Token 交换、ID Token 验证或登录 UI，收到授权码不代表认证完成。

### OIDC 协议适配推进

- 使用 openid-client 6 处理 Discovery、授权 URL 和授权码交换，显式开启 ID Token 签名验证；校验 nonce、issuer、audience 等协议约束。
- 网络端点要求 HTTPS，不跟随重定向；桌面 loopback 回调保留实际响应参数供协议库校验。
- 登录协调器阻止同一连接并发登录，取消或配置变化后拒绝提交旧结果。提交回调仍须原子复核配置并加密保存凭据。
- 租户策略尚未定义通用映射：有 tenant 配置时暂返回 AUTH_TENANT_POLICY_UNSUPPORTED，不能忽略限制后继续登录。
- 已用本地生成的真实 RSA 签名及受控 HTTP 响应验证成功路径、篡改签名、错误 nonce/audience、不安全 issuer，以及取消和配置变更；未验证真实企业 IdP。
- 协议适配和协调器尚未接入设置页。加密会话存储、刷新、退出、扩展授权、认证代理仍待完成；不得将此阶段描述为企业登录可用。
