# 运行中补充信息与待补充区：需求

日期：2026-10-14。状态：首版产品范围与五项交互规则已由用户确认，尚未实现或发布。代码审计基线 `d54463f`。工具名、字段与配额已由 [U0](user-input-u0-results.md) 细化冻结；产品确认不代表接口已可用。

相关：[技术设计](user-input-design.md)、[实施任务](user-input-implementation-plan.md)、[已实现异步表单](async-host-forms.md)。

## 目标与已讨论方向

用户可以在 Agent 运行过程中补充信息；模型可以请求结构化答案。待回答内容显示于聊天框上方，不随消息滚动消失。界面、请求生命周期和执行恢复由宿主负责，内置 Skill 教模型何时及如何使用工具。

支持两类来源，共用现有声明式字段与渲染能力：

| 来源 | 定义方式 | 提交含义 |
| --- | --- | --- |
| 第三方 Skill / Extension 业务表单 | 已注册的确定性模板，例如差旅报销 | 保持已有 chat / operation 边界；业务写入仍走授权路由 |
| 模型生成的补充表单 | 根据对话按受限范式动态组织，例如旅游攻略缺少日期、预算 | 补充当前任务信息，不携带业务 API，不授权外部业务操作 |

UI 使用现有 shadcn/ui 组件与宿主多语言机制。无业务特例，不绑定旅游或报销字段。第三方 Skill 可直接使用宿主工具，不必依赖内置 Skill。

## 用户场景与要求

- R01 运行中手动补充：输入框允许发送补充文字，同时保留独立停止按钮。输入内容只有在宿主持久接受后才清空；失败保留可恢复内容，并明确显示排队、已送达或待核实。
- R02 模型请求：缺少多个关联信息时展示表单；已知信息预填，避免重复提问。仅缺一个简单信息时允许普通提问；表单不成为每次对话的强制门槛。
- R03 待补充区：同一聊天的未回答事项在固定 dock 可见。多请求展示数量与来源，一次展开一个；允许收起或稍后填写，草稿不丢，收起不等于取消。长表单内部滚动，不遮住输入与停止入口。
- R04 单一状态来源：历史记录与 dock 引用同一实例，避免两个可编辑副本相互覆盖。提交后 dock 移除待办，历史保留答案摘要及投递结果。
- R05 定向回答：答案关联 requestId、所属聊天及等待上下文；宿主和 UI 不猜测普通文字对应哪个请求；模型可根据明确的用户回答调用工具关联请求，并记录来源消息。歧义或缺失必填信息时继续确认；不得替代业务表单提交或授权。
- R06 局部等待：不依赖答案的工作可继续；依赖答案的工作必须等待。最终输出依赖 B 时不得声称整个任务完成。计划文字 A/B/C 不等于真实独立执行单元。
- R07 生命周期：支持明确的提交、取消、失效、替换；用户已经编辑时禁止模型静默覆盖。取消/跳过不能自动采纳预选项或猜测答案。
- R08 恢复与并发：持久草稿和已提交答案；重复点击、多窗口、轮次结束竞态、休眠/重启不能造成静默丢失或自动重复业务执行。
- R09 权限语义：信息补充与授权可以共享展示区域，但标题、文案、动作类型必须明确区分；填写预算不等于授权付款。动态表单只回到当前聊天，禁止 HTML/脚本/任意请求地址。
- R10 语言与可访问性：模板词典继续按原规范；模型动态文案按用户明确语言要求，否则使用宿主语言。宿主按钮/错误提示本地化；动态业务文本不进行事后机器翻译。支持键盘、读屏、窄屏及不抢输入焦点。

## 已确认的分阶段范围

首版：运行中直接追加文字；统一待补充区；单页动态补充表单；持久请求和答案投递；内置 Skill；第三方已注册 chat 表单可显式接入待补充区。复用现有异步执行，答案投递到原聊天执行上下文。暂不允许把任意 nodeId 写进请求就声称支持局部恢复。

后续：具有明确身份、依赖关系和检查点的执行单元；B 等待时 A/C 可运行、回答后精确恢复 B。无需强制多 Agent，但必须有可验证的调度与上下文恢复能力。

首版暂缓：动态多步骤业务流程、远程选项、附件、密码/Token 收集、动态 operation 绑定、跨聊天投递、模型任意改写用户草稿。现有业务多步骤与授权能力不受此范围取消。

## 已确认决策（2026-10-14）

| 决策 | 已确认规则 |
| --- | --- |
| D1 首版范围 | 运行中补充文字、动态单页表单、固定待补充区；继续无依赖工作，精确步骤级恢复后续实现 |
| D2 用户停止 | 停止当前执行，暂停尚未投递的补充信息；保留请求与草稿。停止后填写只保存，明确点击“提交并继续”或继续任务才恢复执行 |
| D3 稍后与取消 | “稍后填写”只收起、保留待办；“取消此请求”通知模型用户未提供答案，不自动填默认值。仅可选字段允许留空 |
| D4 文字回答 | 模型可用明确用户消息解决补充请求，保存消息引用与结构化解释；歧义继续确认，仅适用于信息补充，不替代业务提交或授权 |
| D5 替换表单 | 模型可提出替换；未编辑的旧表单可直接标为已替换；已有草稿时由用户选择是否采用新表单，原输入保留 |

默认采用一次展开一张表单，其余显示数量；单页使用现有字段类型；无自动提交倒计时；动态表单仅补充当前聊天，不调用业务 API。

## U0 技术细化结果

- U0 已冻结工具名、状态与来源证据、投递和停止竞态、CAS 边界，详见 [施工契约](contracts/user-input/README.md)。
- 配额已冻结：动态表单最多 12 字段、定义 32 KiB、每聊天最多 5 个待补充请求；完整限制见施工契约。验收前不写入已支持能力清单。
- U0 工程决策：内置 Skill 随应用分发、只读、按需引导；停用仅影响自动引导，不关闭宿主或第三方合法能力。U8 验证具体注入机制。
