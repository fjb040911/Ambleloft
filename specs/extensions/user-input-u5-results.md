# U5 模型工具与运行时绑定

日期：2026-10-14。U5 代码与专项验证完成；任务界面启用仍依赖 U6。当前普通任务不公布新增工具，以免产生用户无法填写的请求。运行时内部 `inputToolsEnabled` 开关供 U6 就绪后统一启用，不是用户设置或 SDK 接口。

## 实现范围

- 新增 `core/inputs/model.cjs`，提供 input_capabilities、input_list、input_request、input_read_answer、input_resolve_from_message 五个工具。通过现有带随机认证凭据的内部 MCP 接入，运行时绑定真实聊天与执行上下文；结束、取消或移除上下文后拒绝调用。
- 工具参数复用冻结 Schema，禁止模型输入聊天 ID、来源身份、提交操作或接口地址。错误使用 `{ok:false,error:{code,message,details?}}`，MCP 设置 isError。取消、替换工具仍属 U7，不公布为已实现能力。
- 请求完成持久化后立即返回，不等待用户填写。同 requestKey 同定义返回同一请求，created=false；返回当前状态与 revision，包含终态重试。模型工具的幂等身份不随宿主语言切换变化，保留创建时的文案快照。
- 模型列表仅投影标题、理由、状态、版本、是否编辑及投递状态；不返回未提交草稿或提案答案。read_answer 只返回已确认答案及投递回执。
- 静态模板通过 `input_request.source={kind:"template",key}` 显式选择补充流程，真实来源、版本、摘要与语言由宿主目录绑定。仅接受受限单页 chat 模板；拒绝业务 operation、多步骤、group-toggle、联动与隐藏字段。原 forms_present、原表单授权和提交流程不变，不新增模板清单字段。

## 文字回答与草稿保护

- 新的宿主主动文字入口记录 inputSource=user，并在引擎确认送达后标记 delivered。运行中追加文字继续使用 U1 的可信标识。模型无权通过工具参数伪造这些标识。
- 仅从本聊天持久消息读取证据；助手消息、表单自动投递、未送达消息、没有可信来源的历史消息均不可引用。列表最多 20 条，每条 2000 字符，总 JSON 不超过 32 KiB，明确标识截断；resolve 可按 ID 引用更早的可信消息。
- 当前草稿记录没有区分手工草稿和扩展创建草稿的可信来源，因此首次从草稿发送的文字保守地不作为自动关联证据；后续用户主动文字与运行中补充不受此限制。不得反推旧数据的作者；后续若扩展此范围，需先补齐草稿来源追踪。
- 完整字段值通过现有字段验证；宿主冻结真实消息快照与模型解释，二者分开保存。宿主验证来源真实性与值是否合法，不声称能自动判断模型的语义理解是否准确；歧义或部分回答应继续询问。
- 未编辑请求在同一事务内保存答案并置 answered，不创建新的 outbox，避免重复发送模型已经收到的原文。
- beginEdit 可能先于尚未保存的前端输入，因此凡已开始编辑的请求都先保存 confirmationRequired 提案，不仅比较已保存草稿。请求仍 pending，草稿不变；确认/拒绝提案操作和界面由 U6/U7 完成。本阶段不自动确认。
