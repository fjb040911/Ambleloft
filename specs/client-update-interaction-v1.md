# 客户端更新交互设计 v1

2026-11-04 · 待实施的交互规格。依赖 [更新技术流程](client-update-flow-v1.md)。延续现有 SettingsWorkspace、SettingsCard、ManagementDialog 与应用通知样式，不另建视觉体系；本文线框表达布局与行为，不是已实现界面。

## 1. 用户旅程与入口（按截图修订）

检测到版本 → 活动栏左下角显示独立蓝色圆环按钮 → 悬停了解版本 → 点击直接下载 → 圆环显示进度 → 就绪后点击查看重启选项。

更新按钮位于活动栏底部、设置和关于按钮上方；不占用或改变关于按钮，不向消息中心额外推送。无可用更新时隐藏更新按钮，设置与关于按钮保持原位置。下载/失败/就绪期间保持可见。点击开始下载即为用户下载授权，无二次下载确认；不等于同意安装。

“关于”和“设置 → 版本与更新”继续复用完整更新卡片，支持查看说明、下载、取消、重试及重启。用户可以从这些入口先看说明再下载，也可以用蓝色按钮直接开始。原生菜单检查更新打开关于。所有入口共享同一主进程状态；关闭页面不停止下载。

全局固定活动栏模式，移除设置 > 通用的“导航布局”。旧用户保存的 classic 值不再影响渲染；保留旧字段读取兼容，不破坏工作区数据。本次导航代码已调整，更新器与按钮接入仍待实施。

## 2. 宿主检测规则

主进程是检查与下载的唯一拥有者；窗口订阅统一状态。客户端版本取 app.getVersion()，引擎版本取经过检查的内置构建信息，远端候选由固定 GitHub provider 和 stable 策略解析。

启动稳定 60 秒后检查，随后每 6 小时加随机抖动检查；唤醒/网络恢复仅在过期且退避已结束时补查，不每次聚焦窗口都请求。手动检查优先执行，但合并在途请求并遵守服务端限流。主进程不会请求模型参与版本检测。

候选需满足：高于当前版本、正式 stable、当前平台/架构有可安装产物。版本比较使用语义版本规则。相同/较低版本不提示升级，预发布不泄漏进稳定通道。

自动检查失败静默保留最后成功结果，设置中标注失败时间；手动检查失败在页面立即说明原因。检查未成功不能显示“已是最新版本”，应显示“尚未检查”或“暂时无法检查”。

默认自动检查开启、自动下载关闭。用户可关闭自动检查，手动检查继续可用；自动下载只作用于实际检查到的版本，不隐含重启许可。设置作用于本机安装的客户端而非当前项目，跨窗口同步。

## 3. 蓝色更新按钮的精确交互

参照用户截图：空心蓝色圆环，无中央问号，不以数字占据图标。按钮点击区域 40×40 px，圆环外径约 24 px、描边 3 px，使用适配深浅主题的蓝色 token。按现有活动栏间距对齐。进度从顶部顺时针增长；环底轨道使用低强调色。

| 状态 | 外观 | hover / focus 提示 | 点击动作 |
|---|---|---|---|
| 无更新/首次检查 | 隐藏 | — | 关于和设置仍可手动检查 |
| available | 完整蓝色空心圆环 | 新版本 {version} 可用，点击下载 | 立即发起下载，切换下载状态 |
| downloading | 底轨＋蓝色进度弧 | 正在下载 {version} · {percent}% | 打开关于的下载详情，不重复下载 |
| 进度未知 | 不定进度弧 | 正在下载更新 | 打开下载详情 |
| verifying | 不定进度弧 | 正在校验更新 | 打开校验详情 |
| ready | 完整蓝环＋中心向上箭头 | 更新已就绪，点击查看重启选项 | 打开关于的重启操作，不直接重启 |
| waiting-for-idle | 蓝环＋小钟表 | 将在任务结束后更新，点击管理 | 打开阻塞项和取消计划 |
| 下载或校验失败 | 静态圆环＋叹号 | 更新未完成，点击查看原因 | 打开错误及重试，不自动重下 |
| 安装成功 | 隐藏 | — | — |

发现新版本不额外弹出通知，单靠常驻蓝色按钮提示。下载就绪时可在未打开更新页的活动窗口显示一次非阻塞“更新已准备好”提示；按版本去重，不增加消息中心未读数。

完整蓝环在 available 表示可用动作，不标为 100%；下载进入时明确切换为进度轨道，tooltip 改为下载阶段。未知总量不伪造百分比。差分转全量在详情中解释，环形进度可重新开始；校验阶段不能冒充安装就绪。

首次点击后立即反馈“正在准备下载”，主进程请求未返回时也锁定重复点击；失败恢复错误态。取消下载仅在关于/设置详情进行，避免用户点图标查看进度时误取消。取消后回到 available。点击查看过版本不隐藏按钮；“跳过此版本”才隐藏该版本提示并停止其自动下载，手动检查仍可显示。

所有窗口同步状态，tooltip 支持键盘 focus，按钮 accessible name 随状态变化，阶段变化 aria-live=polite，百分比不每帧播报。进度弧不拦截点击；reduced motion 下取消旋转，使用静态阶段提示。布局预留底部空间，出现按钮不能挤动设置和关于入口。

## 4. 页面信息结构与线框

“关于”沿用当前品牌介绍、版本信息和帮助链接。在版本信息后、产品帮助链接前插入紧凑更新卡片。品牌与版本始终可见，长说明可展开，不把主操作挤到弹层视口之外。

```text
关于 AmbleLoft                                  [关闭]
[图标] AmbleLoft
当前版本 0.9.0 · Codex 0.153.4

┌ 发现新版本 0.9.1 ──────────────────────────┐
│ 本次更新摘要（最多三条，可展开）            │
│ [查看更新说明 ↗]                           │
│ [下载更新]  [稍后]                     [⋯] │
│ 下载期间可以继续使用，安装时需要重启。      │
└───────────────────────────────────────────┘
[官方网站] [使用文档] [GitHub]
[更新设置]                           [复制版本信息]
```

同一张卡片在下载和就绪时原位变化：

```text
正在下载 0.9.1                      42%
[━━━━━━━━━━━━──────────────────]
可以关闭此页面，下载将在后台继续。  [取消下载]

更新已准备好 · 0.9.1
[重启并更新] [空闲时更新]
安装前会检查运行中的任务并保存状态。
```

无新版本时卡片收敛为“当前已是最新版本 · [检查更新]”；尚未成功检查时不能使用该文案。失败在原位显示原因和重试。关于页不要求跳转设置才能完成更新。

设置页复用同一个 UpdateCard，下面增加偏好：

```text
版本与更新
保持 AmbleLoft 为最新版本。

当前版本  0.9.0                    [检查更新]
Codex 引擎  0.153.4
上次成功检查：今天 14:30

┌ AmbleLoft 0.9.1 可用 ──────────────────────┐
│ 发布日期 · 稳定版                           │
│ 本次更新                                   │
│ • 宿主功能与修复摘要                        │
│ • 引擎是否变化（仅有可信发布信息时展示）     │
│ [查看完整发布说明 ↗]                        │
│                                            │
│ [下载更新]  [稍后]                 [⋯]  │
│ 下载期间可继续使用，安装时需要重启。        │
└────────────────────────────────────────────┘

更新偏好
[开] 自动检查更新
[关] 发现新版本时自动下载
     下载完成后，由你决定何时重启。
```

版本号和时间为示例。发布说明按安全 Markdown 子集渲染，拒绝原始 HTML 和执行内容；链接仅允许 http(s)，在外部浏览器打开。没有发布说明时显示“此版本未提供更新说明”，不生成虚构修复内容。

设置页面保留当前版本区和偏好区，只替换中间状态区域，避免进度变化导致整页跳动。窄窗口按钮换行，正文自然折行，不水平滚动。

## 5. 状态、文案与动作

| 状态 | 主文案 | 主动作 | 次动作 / 后续 |
|---|---|---|---|
| 尚未检查 | 尚未检查更新 | 检查更新 | — |
| checking | 正在检查更新… | 禁用检查 | 不弹模态 |
| 无更新 | 当前已是最新版本 | 检查更新 | 显示成功检查时间 |
| available | {version} 可用 | 下载更新 | 稍后；菜单跳过 |
| downloading | 正在下载更新… | 无 | 取消下载 |
| full-download | 正在下载完整更新包… | 无 | “未能复用旧包，将下载完整更新”；取消 |
| verifying | 下载完成，正在校验… | 无 | 短暂禁用取消，直到结果确定 |
| ready | 更新已准备好，重启后生效 | 重启并更新 | 空闲时更新；稍后 |
| waiting-for-idle | 将在任务结束后更新 | 查看阻塞任务 | 取消自动重启 |
| saving | 正在保存并准备重启… | 无 | 保存失败则停止安装 |
| installing | 正在重启并安装更新… | 无 | 界面退出，安装器接管 |
| check-failed | 暂时无法检查更新 | 重试 | 网络/限流原因与下次可重试时间 |
| download-failed | 更新未下载完成 | 重试下载 | 查看诊断；继续使用当前版本 |
| verify-failed | 更新包验证失败，未安装 | 重新下载 | 导出诊断；无“仍然安装” |
| recovery-required | 更新后启动检查未通过 | 查看恢复说明 | 导出诊断；不显示虚假成功 |

下载进度仅展示更新器确实提供的数据。无法取得准确网络总量时使用阶段进度，不伪造剩余时间或显示“已节省 XX%”。若回退全量导致进度重新计算，明确说明，不让百分比无解释倒退。取消后回到 available；缓存保留策略由更新器管理，按钮称“重新下载”或“下载更新”，不承诺未经验证的断点续传。

## 6. 重启操作与阻塞任务

用户点击“重启并更新”后先做只读预检，显示一次轻量确认；不在按钮点击时立即关闭运行环境。

空闲时：

```text
重启并安装 AmbleLoft 0.9.1？
当前没有运行中的任务。将保存工作区和草稿，然后重启。
[取消] [保存并重启]
```

存在工作时：

```text
目前还不能重启
2 个任务正在运行，1 个工具调用等待确认。
• 客户资料整理       运行中          [查看]
• 生成交付文档       运行中          [查看]
• 外部系统提交       等待确认        [查看]
安装更新前需要这些工作结束。
[暂不更新] [任务结束后更新]
```

列表还覆盖未保存编辑、终端活动、扩展操作、保存失败和结果未知的提交；跨 profile 不暴露无权查看的标题，只展示通用阻塞数量及必要的切换入口。没有“强制结束全部并更新”。查看任务返回原业务位置，用户按既有流程处理；返回更新页保持同一目标版本。

“任务结束后更新”是对该版本自动重启的一次授权。本次应用运行内有效；取消立即撤销，重启应用后不自动沿用。等待时正常使用，新的任务可继续进入并推迟安装。

空闲后显示可取消的 10 秒提示“更新将在 10 秒后重启”，置于应用全局可访问位置，不抢焦点。倒计时期间新任务出现则返回等待；结束后原子关门并重检。重检通过才保存安装，失败则显示阻塞原因。后台也遵循已授权倒计时；该行为在授权按钮旁说明。用户主动“保存并重启”无需再次倒计时。

最终保存阶段暂时禁用新的提交和编辑，显示状态；进入安装器之前仍可从失败返回正常使用。门禁期间自动触发延后，用户动作明确告知“正在准备更新，请稍后重试”，不让按钮无反馈。

## 7. 失败、重启与版本变化

- 断网：保留当前工作，下载失败后允许重试；不把网络故障显示成安装失败。
- 空间不足：显示所需/可用空间（仅在可准确计算时），引导清理后重试，不自动删除用户文件。
- 保存失败：显示具体资源及重试入口，取消安装后恢复编辑；不称“已安全保存”。
- 等待超过 10 分钟：本次自动重启计划取消，回到 ready 并说明“任务仍在进行，已推迟更新”；不突然于更晚时间自动重启。
- 安装后仍是旧版本：显示“更新未完成，当前仍为 {version}”，允许重新下载/查看诊断，不无限启动安装循环。
- 新版本启动失败：进入技术流程定义的恢复界面，不派发后台任务，不自动重放未知提交。
- ready/等待期间发现更新版本：不静默替换已批准目标。提示“还有更新的版本”，用户选取后撤销原安装计划并重新下载；旧 ready 状态在新包校验完成前可保留，但只能有一个安装目标。
- 下载期间再次打开页面：订阅现有任务；多窗口重复点击使用同一版本与 revision 幂等处理。
- 正常退出：没有安装授权就不更新。已经授权但尚未到安装阶段的普通退出，不转换成安装；计划随应用退出失效。
- Linux：页面显示版本检查结果与“前往下载”，说明本平台当前需手动安装。开发环境显示“开发模式不执行自动更新”。

## 8. 无障碍与视觉约束

复用现有 Button、Badge、Alert、SettingsCard、ManagementDialog 及主题 token；普通更新采用中性/品牌状态，红色只用于失败。每个状态至多一个主按钮，危险和次要操作不抢主层级。

进度条具备可访问名称，状态用 aria-live=polite，限频播报阶段变化而非每个百分比。倒计时只播报起始与即将重启，取消按钮始终可键盘到达。模态管理焦点并在取消后回到触发器；ESC 在可取消阶段关闭确认，不取消已经开始的安装。支持中英文、深浅主题、键盘、缩放及 reduced motion；无闪烁红点、循环庆祝动画。

## 9. 交互验收

1. 自动发现显示独立蓝色按钮；首次点击直接下载，下载期间点击打开详情。
2. 手动检查有即时反馈；失败不会冒充最新版本。
3. 下载切换页面仍继续；取消不会触发全量回退重下。
4. ready 状态普通退出不安装，需真实平台测试。
5. 运行中点击重启显示准确阻塞列表，不停止任务。
6. 空闲安装可撤销；倒计时期间新增任务会推迟安装。
7. 草稿保存失败不退出，恢复编辑不丢输入。
8. 重复按钮/窗口操作不重复下载、安装或派发。
9. 成功只在新版健康检查通过后显示；未知任务不重发。
10. 键盘、窄窗口、中英文和主题切换下操作完整可达。
11. 关于和设置的同版本、进度、失败与操作即时同步，无重复下载；关闭页面后蓝色按钮仍反馈进度。
12. 旧 classic 用户也进入活动栏；设置不再出现导航布局，蓝色圆环不挤动设置或关于按钮。

交付时需提供上述状态的真实界面截图及连续点击路径；本文只定义交互，尚无渲染或安装验证。
