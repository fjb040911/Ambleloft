# 项目关系与任务编排设计

状态：实现方案 · 2026-11-03

## 目标

让用户在已有任务流程图上确认“谁负责、在哪个项目执行、依赖哪个项目”，避免 Agent 仅凭项目名称猜测职责或把已关联项目当作已连接的执行环境。适用于任意项目空间，不绑定某个测试项目。

## 交互流程

1. AI 根据讨论、空间成员及已保存的项目关系生成可编辑草案。项目不确定时留空，不能为了绕过检查将施工任务改为讨论任务。
2. 草案直接显示依赖图。节点区分待关联、待确认与已确认；点击节点后，在图下原位编辑，不弹第二层窗口、不新增侧栏。
3. 选择负责人和主执行项目；填写该项目职责，确认是否需要其他项目。跨项目关系包含目标项目、类型（接口调用、产物交接、共享契约）和具体交接约定。无跨项目依赖也需要明确确认。
4. 已确认且适用的空间关系直接带入，无需每轮重复确认；没有空间配置时，可复用同空间历史中一致的已确认关系。历史存在冲突则重新引导，不替用户选择。AI 新提出或修改的关系仍须确认。同负责人、同执行项目的未确认节点可一次应用相同配置。
5. 用户可显式“保存到空间供复用”。这只更新该主项目的职责和出向关系，不修改成员授权。以后规划复用这些信息。
6. “检查并保存草稿”执行确定性校验，不调用模型、不重写节点。通过后才显示确认并启动。需求本身仍有未回答的问题时不能跳过原有补充流程。
7. 保存计划时固定每个节点的职责和关系快照。空间以后修改关系，不静默改变已保存或执行中的计划。

## 信息模型

- 空间保存 projectContext：项目职责列表 + 有方向的项目关系。源项目使用目标项目的接口、产物或契约。关系不是任务依赖边。
- 节点保存 projectBinding：responsibility、relations、confirmed。源项目为节点 projectId；ownerId 和 projectId 仍是实际执行授权的唯一来源。
- 计划的 packages.definition 和版本历史保存关系快照；执行 prompt 接收相同快照，以及项目 ID、名称、类型、执行路径等事实。
- SSH 凭证不进入模型上下文。连接配置不等于实时可用；运行时需核验当前状态，不能把旧报错描述为当前断连。

## AI 补齐闭环与新一轮讨论

1. 首次整理任务时，模型同时接收本轮讨论、成员可执行项目、空间关系和历史已确认关系。模型提出节点项目、项目职责、交接约定及建议理由；宿主识别未解决的关系缺口。
2. 草稿中原位展示“补齐项目关系”。采用现有 shadcn 表单组件，预填 AI 建议，项目下拉只提供该负责人有权使用的真实项目。一次聚焦一个节点，可切换待补齐节点；未提交答案保存在本机。
3. “确认关系并用于后续流程”原子保存节点绑定与空间中该项目的职责、出向关系，并再次校验完整性。正文、负责人、验收条件、资料和依赖保持原值。变更主执行项目会使依赖它的节点重新核对关系。原位文案告知会更新可复用的空间约定。
4. 建议不合适时可补充说明，让 AI 仅调整未解决节点的关系。这个请求使用独立输出结构，服务端拒绝模型改动已确认节点；不重新生成整套任务，也不清除未回答的业务问题。
5. 新一轮讨论创建独立草稿，已确认的空间关系优先复用。只有与既有约定一致、授权仍有效、且覆盖该节点跨项目依赖的配置，才能直接标为已确认。新职责、新交接、冲突记录、权限变化和新增依赖仍需补齐。复用来源显示在草稿中。
6. AI 请求失败或取消保留草稿与补充说明；确认失败保留填写答案。表单使用草稿 revision、空间 revision 和 requestKey 校验，避免旧页面覆盖新配置。空间记录通过现有数据库持久化；已保存计划始终使用自己的关系快照。

关系表单负责有限的职责和交接问题；需要增删多条关系时也可使用下方节点配置。业务需求问题仍走原任务引导，不能用关系确认替代业务决策。

## 校验和状态

- 负责人必须是空间成员；主执行项目必须同时属于空间和该成员获分配的项目。
- 所有尚需执行的施工节点启动前必须确认项目职责和关系。源与目标不同，目标属于空间，关系类型及说明完整，不允许重复关系。
- 若节点直接依赖另一个项目的施工节点，必须描述与那个项目的关系。依赖关系仍须无环，按已有“上游验收后调度”规则执行。
- 修改负责人、主项目、依赖、职责或关系会使当前节点的确认失效；上游换项目后，下游检查也会检测缺失关系。
- 保存草案可不完整；启动、恢复和重试再次校验，调度发出执行请求前再校验，防止绕过前端。
- 关系仅说明协作约定，不证明网络连通，也不自动给 Agent 跨项目读写、SSH 或端口转发能力。需要准备环境或建立连接的工作，应有明确节点及验证/验收条件；不支持的能力必须报阻塞，不能用反复重试伪装修复。

## 持久化、兼容与并发

- 复用现有空间数据库，增加可选字段，不另建测试项目专用数据。
- 更新空间关系使用空间 revision 乐观锁；冲突提示刷新，不覆盖其他人的改动。删除关联项目时清除对应空间关系，旧计划快照保留。
- 旧计划没有确认记录，不伪造“已确认”。已有运行不强行停止；在后续调度或显式恢复前提示修订计划并确认项目关系。已验收结果不因空间关系更新自动失效。
- 草稿检查依赖草稿 revision 和空间 revision，创建计划时复查；未回答的需求问题不能通过仅检查关系绕过。

## 视觉与组件

复用现有 shadcn Button、Field、NativeSelect、Checkbox、Badge；沿用宿主主题。节点详情采用一层分组、标签清楚的表单，不叠卡片。流程图与任务配置使用同一选择状态。批量操作明确展示范围和数量。

## 验收标准

- 缺主项目也能预览草案和定位节点，确认后可以创建并启动。
- 自动生成不能伪造用户确认；修改关键字段必须重确认。
- 保存的职责和关系可在后续规划中复用，已有计划保持原快照。
- 跨项目任务缺交接约定、越权、过期版本均被服务端阻止；普通分析节点不强制绑定施工项目。
- Agent 执行输入包含关系快照和项目事实，不包含凭证，也不声称自动拥有其他项目访问能力。
- 中英文、键盘访问、重复检查、返回再打开均保持可用；不以网络在线状态决定能否保存草稿。
