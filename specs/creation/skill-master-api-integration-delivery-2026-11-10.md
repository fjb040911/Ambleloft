# 技能大师 · 接口资料接入交付记录

日期：2026-11-10。目标：显式选择技能大师后，基于接口资料以自然语言引导创建业务工具。本轮没有新增宿主功能，没有改 SDK，没有部署生产或测试云服务。

## 变更与依赖

1. 内置 Skill 与中英文简介：识别宽泛接入意图，资料优先，按业务目标推荐小闭环；专用参考文件按需读取。
2. 资料包：`examples/api-integration/service-desk/docs/`，含独立接口指南、业务规则和 OpenAPI 3.1。文档与服务同为 1.0.0；不包含预生成扩展，方便检验真实生成能力。
3. 配套服务：`server.cjs`，Node 22.13+ 内置 HTTP/SQLite，无安装依赖。loopback 默认演示凭据，独立持久化数据库。具备查询、校验、幂等登记、分页、认证和可选提交后故障注入。
4. 用户操作与行为清单：案例 README 与 evaluation.md；用户可选单文档或整套资料、模糊或明确需求。

宿主既有选择→创建→检查→安装→试用路径保持不变。启动时资源摘要更新会生成新技能版本，已停用状态与历史快照保留。使用最新源码重启应用后再开测试任务；已安装的旧打包应用需要重新打包，不会自动读取开发仓库的 Skill 文件。

## 待验证与实际边界

- `evaluation.md` 中的模型行为用例是待执行清单：没有把提示词内容检查当成真实模型生成验证。
- 本轮未在 Ambleloft 界面由真实模型生成、安装一个新扩展；该试用需与服务测试分开记录。现有创建回归使用固定样例，不能代替这一验收。
- Windows、SSH/Docker、打包版、阿里云部署未验证。
- 演示服务使用单个虚构身份，不支持企业认证、派单/维修、审批、附件、生产限流或多租户隔离。读取不到提交记录始终保守返回 unknown。
- 声明式表单现有动态选项/重复明细等限制未改变。技能推荐支持的路径或说明需要自定义 UI，不伪造控件能力。

## 运行与后续部署

本地运行 `node examples/api-integration/service-desk/server.cjs`，使用案例 README 的测试配置；实际业务数据只留在被忽略的 `.data/` 目录。测试框架全部使用临时目录，不触碰用户数据库。

若要阿里云多人演示：部署独立目录与数据库，以非root服务账号运行，设置独立测试 Key，通过 TLS 反向代理与访问限制暴露接口，保持故障注入关闭，再验证连接/提交/重启恢复。将真实部署地址填入扩展设置，不改 Skill 或业务表单。本轮本地即可测试，未执行以上云端步骤。
