# 技能 / 扩展创建引导

## 使用路径

从源码重启桌面宿主，在项目中新建任务。输入框下的“创建技能 / 扩展”将引导提示词放入草稿并选中内置技能大师，不自动发送、不覆盖已有文字。没有关联项目时先选择项目；内置引导停用时入口指向技能管理。

发送后由模型使用 input_* 收集少量相关信息，复用补充信息的持久化、取消、草稿与回答机制。先理解用途，再建议名称、描述和字段。固定表单本身不需要扩展。

创建卡展示当前阶段与下一步；需求、限制和生成目录收在“方案与验证详情”。模型通过 creation_update 保存已确认的需求；已安装、试用确认等结果由宿主写入。停止任务、重启应用不会清空记录。继续入口只准备提示词，用户发送后要求模型先恢复创建状态和未回答问题。

创建进度使用无卡片外框的轻量状态区，与待补充表单留出明确间距。存在待回答问题时，隐藏重复的下一步说明及“继续创建”操作，以表单为当前主要操作。方案详情默认折叠，展开区域有独立高度限制。补充信息的校验错误以普通数据穿过 Electron IPC 和 contextBridge，在渲染端恢复错误类型和字段信息，避免把漏填误判成未知提交结果而锁住输入；真正的未知提交保留原请求标识核实，不能直接重发新答案。

生成完成后模型调用 creation_prepare。宿主检查真实文件并冻结快照；此步骤不运行生成代码、不证明业务集成成功。“安装并启用”安装该快照，无需用户再次选目录。技能重名可替换或另存；扩展沿用现有代码信任流程。技能更新使旧补充请求失效。扩展安装后可直接进入对应设置页，按现有宿主规则授权配置、填写设置和授权项目。

“准备试用”填入推荐用法，独立技能同时被显式选中，用户发送后在宿主实际运行。用户确认“我已试用，通过”才记录用户验收；记录前核对安装版本仍有效且启用。后续修改需要重新检查、安装与试用。

## 实现与接口

- resources/skills/skill-master：内置引导、创作/验证参考、当前表单与扩展 Schema、SDK 类型及三步差旅起点。
- core/creation/service.cjs：持久化状态、版本冲突、项目边界、快照与安装交接。
- creation_read / creation_update / creation_prepare：通过每轮已认证 MCP 通道绑定当前 run；模型不能用该通道批准安装或验收。
- creation:read / creation:install / creation:trial：由现有桌面授权边界保护的 IPC；creation:event 通知当前任务刷新。
- 状态保存在宿主 SQLite settings 的 creation.v1.<runId>，包括 projectId 和 revision；当前每个任务记录一个创建目标。已确认摘要与 nextStep 由模型更新，未提交的表单草稿仍属于 input_*。
- Skill 安装快照保存在用户数据 creation-bundles 的独立目录；扩展复用 PackageStore 的不可变版本。安装不修改项目中的源文件。旧快照按现有不可变版本策略保留，尚无自动清理入口。

## 扩展性与边界

选择依据是所需能力，不是行业或协议。现有工具足够时生成 Skill；新增运行时、依赖、持久连接、配置、事件或专用界面时推荐扩展。CLI、SSH、GDB Server、厂商 SDK、设备桥与 HTTP 都是可考虑的适配方式。必须确认执行地点、现有工具、生命周期和失败恢复，不能预设 FPGA 都能 SSH 登录。

创建引导只收集影响实现的决策，例如目标平台、工具类别与执行范围。连接地址、工具链路径等属于安装后的扩展配置，通过 manifest.configuration、宿主扩展设置和 context.configuration 管理；凭据走独立安全通道。缺少环境参数不阻塞安装和静态/模拟能力，实际连接操作再检查所需设置。当前配置按扩展保存，不承诺 VS Code 的项目覆盖、路径选择器等尚未实现的能力。示例与实现要求见内置技能 references/configuration.md。

本次没有新增通用远程执行或设备会话协议，也没有交付 FPGA 调试适配器。复杂调试使用实际支持的 Operation 与专用 UI，参数收集才使用表单。缺少设备或服务资料时允许生成明确标记的模拟版本，但不能将其当成实机验收。密码等凭据走宿主凭据交互，不写入创建记录或 Skill。

当前安装入口处理本地项目内的生成目录；SSH 项目可做需求设计与生成，但不能直接从远端目录安装。需要取回本地产物后使用本机安装能力。Skill 升级成扩展不会自动卸载原技能，避免影响旧任务；如名称重叠，试用时选择明确来源，并在技能管理中按需要停用旧版。

## 验证

`tests/creation.test.cjs` 使用真实 SQLite、Skill 导入、FormService 与扩展 PackageStore 验证：
- 三步差旅从文件检查、快照安装、目录发现到填写并提交回聊天。
- 持久化恢复、冲突、目录越界、符号链接、无效表单与快照篡改。
- 取消安装、同名替换、停用版本不能被标记为试用通过。
- Skill 转扩展、原生代码信任与模型工具权限边界。

`tests/e2e/creation.spec.ts` 使用模拟桌面桥验证渲染与交互：入口只填草稿、保留原输入、选中技能、错误重试、重新打开恢复、安装后设置跳转。浏览器测试不代表真实模型或外部硬件验收。

`node scripts/test-creation.mjs` 使用隔离的临时配置启动真实 Electron 和固定版本引擎，通过本地确定性模型响应依次调用创建工具，再通过实际界面安装、准备试用并重启验证恢复。源文件使用内置三步差旅示例，测试不评价模型从需求生成代码的质量，也不会使用现有账户、项目或设备。
