# 交付验证

按任务范围检查并报告实际结果。没有执行的步骤明确为未验证，模型阅读源码不算运行通过。

## Skill

检查 frontmatter、引用是否存在、触发描述和用户意图是否一致。具备宿主时导入生成目录，查看是否可以发现。没有宿主时交付完整文件和导入说明，不声称已安装。

## 表单

用目标宿主的 Schema/解析器或实际可用 CLI 验证，不假定存在 validate-form 命令。解析成功不代表交互通过。

在宿主上验证：目录发现、真实 key、渲染、必填/类型校验、预填、前后导航及草稿、最终确认、结构化提交读取。多步示例核实中间导航不发消息；最终数据的步骤 ID、枚举、金额类型正确。关注用户返回修改前置内容后的后续确认。只在涉及生命周期时补重启/来源变化测试。

## 扩展

执行工程实际提供的 build/validate/pack，检查归档包含被引用资源。若接入业务服务，检查服务调用参数、用户身份、结果记录及错误处理。写入测试使用明确授权的测试服务或模拟环境，分别标记模拟和真实接入。未知提交恢复检查应能证明未重复写入，不能只检测出现了一个“成功”提示。

## 最小交付说明

- 交付物与生成目录；如何在聊天中触发。
- 这版完成的业务闭环，以及仍使用模拟数据的部分。
- 实际命令、退出结果、界面检查和证据路径。
- 待用户提供的业务资料或环境条件，只列真正阻塞下一步的内容。

不要把发布、企业身份接入、任意模型质量或跨平台认证列为默认已通过。
