# 设备报修 · 业务与交互说明

版本 1.0.0，与 `01-api-guide.md` 和 `openapi.json` 配套。单独上传接口指南已足够起步；提供整套资料时应交叉核对。

## 确定的业务规则

- 面向当前已认证员工，支持报修设备及查看自己登记的工单。
- 设备从服务查询。名称用于展示，ID 用于调用；不可用设备不能提交。
- 普通工单必须包含设备、标题和故障描述；紧急工单还须说明业务影响。
- 联系邮箱可不填，服务使用当前员工邮箱，不要求用户每次输入身份。
- 只有用户确认后才提交。返回 submitted 表示“已登记”，不代表已批准或已修复。
- 暂不支持照片、文件附件、维修派单、审批、多设备明细及自动关闭工单。
- 同一次提交的业务结果不明时先查证，不能自动创建第二条。

## 可讨论的交互建议（不是接口硬性规定）

推荐“选择设备 → 描述问题 → 核对并提交”，但用户可以调整步骤和文案。用户已在聊天里描述的信息应尽可能预填，仍允许修改。

如果声明式表单暂不支持实时设备下拉，允许先查询设备、在聊天里让用户选定，再预填设备 ID；展示查询到的名称、说明对应关系，提交前重新校验。不要谎称 YAML 可以远端动态加载选项，也不要把设备示例永久写死。

紧急原因仅在选择紧急时显示并必填。提交前核对信息的方式须符合实际宿主能力；简单的“确认”勾选不等于能自动渲染完整摘要页。如果自动汇总预览是用户必需功能，应明确实现途径和限制。

## 不应向最终用户索取的业务字段

服务根地址与 API Key 属于扩展设置；Idempotency-Key 来自提交上下文；申请人、工单编号、状态及创建时间由服务生成。这些内容不应变成普通业务表单中的必填项。
