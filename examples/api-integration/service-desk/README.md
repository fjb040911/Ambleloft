# 技能大师试验：把接口文档接入 Agent

这是一个可运行的虚构设备维修系统，不是已生成好的扩展。把 `docs/` 提供给技能大师，从需求开始生成自己的扩展，检验它是否能读懂接口、设计表单并完成接入。

## 在 Ambleloft 中开始

1. 更新源码并重启 Ambleloft，使内置技能资源更新。无需手工导入或覆盖技能大师；若此前停用过，请先启用。打包版需使用包含本次资源的新版应用。
2. 新建一个本地测试项目，例如 `~/work/skill-master-service-desk-trial`。源文档可以作为附件，也可将 `docs/` 复制到该项目中的 `api-docs/`。输出放另一个子目录，不改本案例服务源码。
3. 在聊天输入框选择“技能大师”，附上 `docs/01-api-guide.md`，或整套 `docs/`。
4. 输入下面的提示。先用模糊版观察它如何引导；再用新任务测试明确版。两种都不需要提前知道技术名词。

**模糊版：**
> 阅读这些接口设计文档，帮我接入 Agent，让同事可以在聊天里办理业务。

**明确版：**
> 阅读这些接口文档，让同事在聊天里报修设备：选设备、描述故障、确认后提交，并能查到工单。请引导我做出可安装的工具。

**确认推荐范围时可回复：**
> 先做设备报修和查询。可以先在聊天里查询并选择设备，再填表；紧急时补充业务影响，其他按推荐来。

不要把这里的测试操作说明当成接口资料一起提供，避免模型只是复述期望流程。

## 启动测试服务

需要 Node.js 22.13+（使用内置 SQLite；本次在 Node 24 验证）。无第三方依赖，无需 npm install。

在此目录执行：
```sh
node server.cjs
```

默认 `http://127.0.0.1:47835`，数据在 `.data/service-desk.sqlite`，重启保留。健康检查：
```sh
curl http://127.0.0.1:47835/health
```

生成并安装扩展后，在宿主的扩展设置中填写服务根地址，通过宿主凭据输入填写本机演示 Key：`local-demo-key-not-for-production`。这只是公开的虚构测试值；生成代码应从凭据服务读取，不能硬编码。身份检查调用 `/api/v1/me`。在正常表单中不填写 API 地址、Key 或申请人。

支持环境变量 `DEMO_HOST`、`DEMO_PORT`、`DEMO_DB`、`DEMO_API_KEY`。默认只监听本机；对外监听必须设置自己的测试 Key。服务没有 TLS、多租户认证、运维限流或企业权限体系，不宜直接公开部署。

需要验证结果不明的恢复时，停止原服务，再运行：
```sh
DEMO_FAULTS=1 node server.cjs
```
测试客户端第一次 POST 带 `X-Demo-Fault: after-commit`，会收到 503，但记录已经落库。通过原提交标识查询应恢复成功，数据库只能有一条工单。不要把故障开关作为用户业务功能。

## 预期交付和手动验收

- 技能大师先读文档，指出可做的业务；明确版不再重复问做什么。
- 给出文档对应的字段和步骤建议，不索取地址/Key来阻塞创作。
- 生成包含业务 Skill、声明式表单、Node 操作与设置/凭据接入的扩展。
- 普通/紧急两条路径都能试填；紧急缺原因应可继续编辑补充。
- 设备来自真实查询；可先在聊天选定并预填，不承诺动态 YAML 下拉。
- 用户确认提交后得到服务返回的真实编号；查询编号与服务记录一致。
- API Key错误时引导修改设置；改回后可继续，不把填写内容丢掉。
- 模糊提交结果先查询；重启服务后仍能查询，不重复创建。
- 静态检查、安装、模拟服务联调、实际宿主 UI 试用分别记录，不能混为“全部通过”。

更多反例与评分方式见 `evaluation.md`。宿主没有新增入口或自动识别逻辑，本轮只增强技能规则和参考资料。

## 自动验证

在宿主仓库根目录：
```sh
node --test tests/skill-master-api-demo.test.cjs tests/skill-master-bundle.test.cjs tests/creation.test.cjs
```
服务测试启动隔离临时数据库和随机端口，验证真实 HTTP 响应符合 OpenAPI schema、条件校验、认证、分页、幂等、重启恢复及故障注入。它不代表真实模型已经自动生成合格扩展，也不代表宿主界面或阿里云部署通过。

本轮不依赖阿里云即可完整测试。需要多人远端演示时，再独立部署测试实例，配置 TLS、独立测试凭据和网络访问控制；不要复用生产数据或现有服务数据库。
